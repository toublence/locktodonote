## 2 먼저 출시 상태를 확인할 항목

최근 작업에는 반복 삭제와 날짜 표시 수정이 있다. 새로 같은 수정을 만들기보다 수정본의 실제 배포 여부를 확인한다. [기존 수정 보고서](/Users/nam/projects/ios/locktodonote/docs/review-fix-report-2026-10-28.md)

- 반복에서 오늘만 삭제·앞으로 중단·전체 삭제가 구분되고 다음 실행에서 되살아나지 않는다.
- 날짜 조회와 잠금화면 날짜 고정이 구분되고, 오늘 자동 표시로 복귀할 수 있다.
- 구매·복원 뒤 Pro가 유지되고 해당 결과가 실제 표시된다.
- 기존 사용자 데이터와 기존 평생·연간 구매 권한을 보존한다. 레거시 `yealy` 상품 ID를 임의로 정리하지 않는다.

Live Activity는 무기한 실행되는 화면이 아니다. Apple 문서상 활성 상태는 최대 8시간, 종료 후 잠금화면 잔류까지 최대 12시간이다. ‘유료라서 24시간 영구 표시’나 ‘앱 종료 상태에서도 항상 정시에 전환’을 판매 약속으로 쓰지 않는다. 위젯과 재시작 안내를 포함해 실제로 제공하는 동작을 보여준다. [Apple ActivityKit 제약](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)

## 3 첫 개발 묶음

### 자동화 초안과 결과 미리보기

시작점은 기존 자동화 화면의 ‘업무 시간에 맞춰 설정’이다. 시간·요일·표시 대상을 정한 뒤 현재 시각과 다른 시간대의 결과를 미리 본다. 무료 사용자도 여기까지 진행할 수 있다. 이후 ‘이 설정으로 자동 전환’에서 체험 또는 구매를 안내한다.

변경 대상은 [SmartLockScreenView](/Users/nam/projects/ios/locktodonote/LockTodoNote/Features/Templates/SmartLockScreenView.swift), [AutomationTabView](/Users/nam/projects/ios/locktodonote/LockTodoNote/Features/Automation/AutomationTabView.swift), [AppEnvironment](/Users/nam/projects/ios/locktodonote/LockTodoNote/App/AppEnvironment.swift)다. 무료 초안과 실행 권한을 분리하고, 여러 구성 초안 때문에 기존 무료 저장 한도를 우회하지 않도록 한다.

완료 기준:

- 무료 상태에서 구성 저장을 미리 강요하지 않고 한 개의 자동화 초안을 끝낼 수 있다.
- 겹치는 시간·누락된 구성은 구매 전에 설명한다.
- 결제 취소와 복귀 후에도 초안이 보존된다.
- 구매 성공 후 같은 초안이 적용되고 적용 성공 또는 복구 방법을 표시한다.
- iOS 갱신 지연을 실제 자동화 오류와 구분한다.

### 미리알림 연결 미리보기

‘연결하면 무엇이 보이는지 확인’ → 접근 권한 설명 → 동의 → 목록 선택 → 결과 미리보기 → Pro 활성화 흐름을 제공한다. 권한 거절 시 샘플 또는 기존 직접 작성으로 돌아간다. 미리보기에서는 Apple 원본에 쓰지 않는다.

변경 대상은 [AppleRemindersSettingsView](/Users/nam/projects/ios/locktodonote/LockTodoNote/Features/Settings/AppleRemindersSettingsView.swift), [ReminderSyncService](/Users/nam/projects/ios/locktodonote/LockTodoNote/Core/Reminders/ReminderSyncService.swift), [AppleRemindersClient](/Users/nam/projects/ios/locktodonote/Packages/LockTodoNoteShared/Sources/LockTodoNoteShared/Models/AppleRemindersClient.swift)다. 현재 `isPro`에 묶인 연결 경로에 무료 실제 동기화를 무작정 허용하지 않고, 저장과 원본 변경 없는 미리보기 경로를 둔다.

완료 기준은 선택한 실제 항목의 미리보기, 구매 후 같은 목록 연결, 취소 시 원본 무변경이다. 계정의 권한 철회·목록 삭제·잠긴 기기에서도 로컬 완료와 Apple 완료가 불일치하지 않도록 기존 실패 처리를 유지한다.

### 결제 화면의 결과 중심 구성

기존 `source`별 문구와 구매 후 적용 흐름을 재사용한다. 상단에는 사용자가 만든 결과, 그 아래에는 ‘현재 기능의 계속 사용 / 관련 자동화 / 광고 제거’처럼 해당 목적에 맞는 핵심 혜택 3개를 둔다. 상세 혜택은 펼쳐 볼 수 있게 한다.

자동 전환은 ‘업무 시간에는 업무 할 일만’, 미리알림은 ‘두 번 입력하지 않고 잠금화면에서 완료’를 먼저 설명한다. 기능이 적용된 것처럼 보이는 가짜 성공 화면을 쓰지 않는다. 가격과 기간·자동 갱신 조건은 현재 StoreKit 정보에 맞춰 표시한다.

Calendar 읽기용 권한은 OS상 전체 접근이 필요하다. 지원 OS에 맞는 사용 설명 키와 권한 분기를 적용한다. 일정 생성·삭제를 하지 않는다는 앱의 실제 범위도 설명한다. [Apple 권한 문서](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)

출시 판단 시 하루 종일 일정·겹치는 일정·권한 거절·권한 철회·날짜 경계·시간대 변경·빈 목록·완료 실패를 확인한다. 이번 분석에서는 빌드나 기기 테스트를 수행하지 않았다.

## 5 루틴의 최소 제품 사양

기존 개별 반복 항목 위에 `Routine`과 날짜별 진행 상태를 추가한다. 하나의 루틴은 이름·단계 목록·실행 요일을 가진다. 첫 버전은 사용자가 시작하고 완료하는 흐름으로 제한하고, 위치 자동 실행이나 타이머의 정확한 백그라운드 종료는 제외한다.

루틴 1개는 무료, 여러 루틴과 요일별 변형은 Pro로 제안한다. 일반 할 일과 일반 반복은 기존 정책을 유지한다. 같은 날 두 번 시작했을 때 기록이 중복되지 않고, 날짜별 완료 기록이 보존돼야 한다. ‘오늘만 건너뛰기’와 ‘반복 종료’도 구분한다.

초기 범위에서는 통계 화면을 크게 만들지 않는다. 현재 단계와 진행률이 실제로 사용되는지 확인한 후 주간 기록 비교를 추가한다.

## 6 실험 순서와 판단 기준

동시에 가격·광고·체험·온보딩을 바꾸면 원인을 알기 어렵다. 아래 순서대로 한 실험씩 진행하고, 소규모라 비교가 불가능하면 같은 국가·유입·버전으로 나눈 전후 관찰임을 명시한다.

| 순서 | 가설과 변경 | 주 평가 | 보조 및 보호 지표 |
| --- | --- | --- | --- |
| 1 | 결제 전 자동화·연동 결과를 만들면 구매 이유가 선명해진다 | 대상 신규 사용자의 D35 첫 실제 유료 전환 | D7 핵심 행동 재사용, 구성 완료, 환불, 표시 실패 |
| 2 | 평생 선택을 바로 보여주면 구독을 원하지 않는 사용자의 결제가 늘어난다 | 전체 대상의 D35 첫 유료 전환 및 다운로드당 수익금 | 상품별 비중, 이후 갱신 수익, 환불 |
| 3 | 첫 효용 경험까지 앱 오픈 광고를 줄이면 구매할 사용자가 더 남는다 | D7 핵심 행동 재사용 및 D35 총수익금/다운로드 | 첫 입력 소요 시간, 운영 광고 수익, 구매 전환 |
| 4 | 실제 자동화 체험이 템플릿 체험보다 첫 과금을 늘린다 | 체험 시작자의 동일 관찰 기간 내 첫 과금 | 실제 기능 사용, 체험 만료 후 기록 접근, 중복 체험 |

배정은 사용자 또는 설치 단위로 고정하고 양쪽의 가격·유입 조건을 동일하게 둔다. 기존 유료 사용자는 무료→유료 전환 실험 분모에서 제외한다. 실험 중 상품을 바꾸거나 임의로 유리한 날짜에서 종료하지 않는다.

초기 사업 목표는 동일 조건의 D35 첫 유료 전환 5%, 이후 7%다. 자동화 미리보기 완성률과 구매 후 사용 성공률을 선행 지표로 본다. 예를 들어 대상 50명이 미리보기를 보았는데 10명도 구성을 끝내지 못하면 새 기능 확장보다 설정 흐름을 먼저 수정한다. 이 수치는 내부 점검선이며 통계적 성공 판정 기준은 아니다.

D35 전환 3.28%에서 5%의 차이를 작은 표본으로 확정할 수 없다. 양측 5% 유의수준·80% 검정력의 단순 두 비율 근사에서는 집단별 약 2,100명의 성숙한 신규 다운로드가 필요하다. 유입·기기·중복 사용자와 지연 과금을 반영한 실제 실험 설계는 별도다. 충분한 표본이 없으면 전환 건수·분모·불확실성 범위를 제시하고 학습 결과로만 판단한다.

## 7 최소 이벤트와 지표

| 이벤트 | 상태 | 주요 속성 |
| --- | --- | --- |
| `pro_setup_started` | 추가 제안 | 기능, 진입 경로, 실험군 |
| `pro_setup_completed` | 추가 제안 | 기능, 초안 ID, 필요한 권한의 상태 |
| `pro_value_previewed` | 추가 제안 | 기능, 실제 내용/샘플 구분 |
| `paywall_seen` | 기존 재사용 | 진입 경로, 상품 구성, 실험군 |
| `purchase_started`, `purchase_completed` | 기존 재사용 | 시도 ID, 상품, 체험 여부. 과금 집계와 분리 |
| `pro_feature_used` | 추가 제안 | 기능, 실행 결과, 이용 권한의 출처 |
| `purchase_value_applied` | 기존 확장 | 템플릿뿐 아니라 자동화·연동에도 적용 결과 기록 |
| 실제 과금·갱신·환불 기록 | App Store 보고서 우선, 이후 거래 기록 보완 | 거래 ID, 원거래 ID, 상품, 환경, 과금일, 통화·금액, 환불 |

`purchaseValueApplied`는 현재 템플릿 미리보기 조건에서 기록된다. 템플릿 이벤트 이름을 자동화 성과로 잘못 해석하지 않고 `feature`와 적용 결과를 확장한다. SDK의 시스템 위젯 갱신 횟수는 사용자가 카드를 본 횟수로 세지 않는다.

주간 대시보드는 누적 IAP, 실제 과금 건수, 신규 유료 사용자, 갱신, 환불, 수익금, 신규 다운로드, D7 핵심 행동 재사용, 성숙한 D35 첫 유료 전환을 표시한다. 할 일 완료·루틴 진행·위젯 액션 등 앱 밖의 실제 행동도 재사용에 포함하되 자동 타임라인 갱신은 제외한다.

세션·사용자 연결에는 동의와 기존 분석 설정을 따른다. 할 일 제목, 메모, 일정 제목, 사진 내용은 분석 속성으로 저장하지 않는다. 동일 거래는 한 번만 집계하고 Sandbox·TestFlight·개발 테스트를 운영 과금에서 제외한다.
