# LockTodoNote 누적 구매 1000건 성장 전략

작성일: 2026년 10월 28일. 목표: 사용자가 확인한 **누적 앱 내 구입 1,000건**. 목표 기한은 미정이다.

**먼저 기존 자동화 기능을 결제 전에 이해하고 체험할 수 있게 만들고, 신규 유료 기능은 ‘다음 일정과 지금 할 일 카드’를 우선 개발한다. 이후 ‘순서대로 진행하는 루틴’을 추가한다.** Pro의 주된 구매 이유를 매일의 일정 확인과 실행으로 강화하는 방향이다. 사진과 테마는 구매를 돕는 보조 혜택으로 유지한다.

추천 순서는 **표시와 데이터 신뢰성 → 기존 Pro 체험 개선 → 일정 통합 카드 → 루틴 → 유입 확대**다. 각 기능의 결제 효과는 아직 검증되지 않은 가설이다. 기능을 모두 만들기보다 첫 두 단계의 결제 전환과 재사용 결과로 다음 투자를 결정한다.

[Apple 분석 대시보드](https://developer.apple.com/help/app-store-connect-analytics/overview/analytics-dashboard), [Apple 코호트 설명](https://developer.apple.com/help/app-store-connect-analytics/monetization/cohorts/)

| 우선순위 | 기능 | 사용자가 돈을 낼 이유 | 현재 대비 변경 | 초기 개발량 |

### 1 기존 자동화를 내 하루로 설정하기

**대상:** 업무와 개인 할 일을 번갈아 보는 사용자, 반복 일정을 자주 만드는 사용자, Apple 미리알림에 이미 자료가 있는 사용자.

현재 ‘구성 저장 → 전환 규칙 작성 → 표시 항목 선택’ 과정을 ‘업무 시간용 / 공부 시간용 / 아침 준비용’ 시작 버튼으로 묶는다. 사용자가 시간과 표시 대상을 고르면 오전·오후·저녁의 결과를 미리 보여준다. 구성 생성은 초안으로 처리하고, 실제 활성화 또는 체험 시작 시 저장한다.

미리알림은 권한 동의 후 선택 목록의 일부를 읽어 미리보기로 보여준다. 무료 미리보기에서는 원본 완료·수정이나 자동 연결을 실행하지 않는다. 결제 후에는 선택한 목록을 다시 고르게 하지 않고 연결을 이어간다. 제목·날짜·반복·삭제까지 양방향 편집되는 것처럼 홍보하지 않는다. 현재 원본 반영 범위는 완료 상태다.

무료는 초안·미리보기와 기존 수동 사용을 제공하고, Pro는 자동 실행·지속 연동·고급 반복을 제공한다. 결제 문구 예시는 **‘매일 아침 업무 할 일이 보이도록 설정하세요’**다. 현행 목적별 결제 화면을 재사용한다.

### 2 다음 일정과 지금 할 일 카드

**대상:** 회의나 수업 시간이 있고, 별도 할 일 앱과 캘린더를 번갈아 확인하는 사용자.

카드 예시: **‘다음 일정 14:00 회의 · 지금 할 일: 자료 보내기 / 질문 정리 / 견적 확인’**. 다음 일정 1개와 사용자가 고른 중요 할 일 최대 3개를 함께 표시한다. 기한이 있는 항목은 그다음 우선순위로 정렬하고 완료된 항목은 다음 항목으로 교체한다. 초기에는 AI 우선순위 추정을 넣지 않는다.

기존 미리알림 연동과 앱 자체 할 일을 재사용하고, 기기에 등록된 Calendar 일정 읽기를 추가한다. Google·Outlook 자체 계정 연결이나 전체 양방향 캘린더 편집은 첫 범위에서 제외한다. 일정이 없어도 할 일 카드로 작동해야 한다.

무료는 현재 기본 카드와 새 카드 미리보기, Pro는 통합 카드의 실제 사용·여러 캘린더 선택·목록 조건 저장을 제공한다. 결제 문구 예시는 **‘다음 일정과 해야 할 일을 한곳에서 확인하세요’**다. 일반 할 일의 기한 입력처럼 이미 제공하는 기능을 다시 잠그지 않는다.

Calendar 데이터를 읽으려면 OS가 요구하는 전체 접근 권한이 필요하다. 앱은 읽기 동작만 제공하더라도 권한 범위를 정확히 설명한다. [Apple EventKit 접근 안내](https://developer.apple.com/documentation/eventkit/accessing-the-event-store)

### 3 순서대로 진행하는 루틴

**대상:** 출근·등교·공부 시작처럼 같은 준비 절차를 반복하는 사용자.

‘가방 챙기기 → 교통카드 확인 → 출발’ 같은 루틴을 한 번 만든다. 잠금화면에는 현재 단계와 **2/4 완료**를 보여주고, 완료하면 다음 단계로 넘어간다. 일반 반복 할 일과의 차이는 묶음의 시작·순서·진행 상태가 있다는 점이다.

무료는 루틴 1개를 완결해서 사용할 수 있게 하고, Pro는 여러 루틴·요일별 구성·고급 반복·기록 비교를 제공한다. 결제 시점은 두 번째 루틴 또는 다른 요일 구성을 만드는 순간이다. 기존 반복 할 일 수에는 새 제한을 걸지 않는다. 주간 통계는 반복 사용의 보조 혜택으로 둔다.

### 후순위 후보

**D-Day 목표 카드:** ‘시험 D-30 + 오늘 공부 3개’를 제공한다. 기존 D-Day 표시를 새 기능이라고 부르지 않고 목표와 할 일의 연결을 판매한다. 공부 목적 사용자의 체험·구매가 확인되면 3순위와 순서를 바꿀 수 있다.

**캡처에서 가져오기:** 사진 선택 → 기기 내 글자 추출 → 항목·날짜 확인 → 저장으로 구성한다. 무료 월 3회 같은 한도는 초기 실험값이며 Pro에서 해제한다. 기본 받아쓰기와 기존 문장 인식은 유지한다. 한국어 인식 품질과 반복 사용이 확인되기 전에는 주 판매 기능으로 삼지 않는다. [Apple Vision 텍스트 인식](https://developer.apple.com/documentation/vision/recognizing-text-in-images)

**보류:** 자체 가족 공동 편집, 본격적인 iCloud 데이터 동기화, 범용 AI 채팅, 테마 팩의 개별 결제. 현재 구매 규모에서는 동기화 충돌·서버 비용·권한 관리 또는 상품 복잡도가 커진다. 필요성이 확인되면 별도로 재평가한다.

## 5 체험과 가격 운영

**첫 개선에서는 가격을 유지한다.** 한국 공개 가격은 월 1,100원·연 7,700원·평생 17,000원이다. 기존 Pro 한 묶음에 추천 기능을 포함하고, 기존 구독자와 평생 구매자의 권한을 보존한다.

첫 실험은 기능별 미리보기와 구매 후 이어하기다. 그다음 동일 가격으로 ‘연간 기본 + 평생 접기’와 ‘연간·평생을 바로 비교, 월간은 추가 선택’을 비교한다. 단기 구매 수뿐 아니라 다운로드당 수익금과 상품별 환불·갱신도 함께 본다. 평생 판매를 숨기거나 월간 결제를 강요해 거래 횟수만 늘리는 방향은 피한다.

체험 정책은 두 종류를 구분한다.

- **현재 앱 내 24시간 체험:** 템플릿만 열린다. ‘전체 Pro 무료 체험’으로 표현하지 않는다.
- **StoreKit 무료 체험:** 상품에 실제 설정된 기간과 사용자 자격을 조회한다. 해당 권한이 생기면 전체 Pro가 동작한다. 과거 문서의 7일 설정을 현재 운영 사실로 간주하지 않는다.

미리보기 개선 후에도 자동화 구매가 낮다면, **결제 등록 없는 7일 핵심 기능 체험**을 두 번째 실험으로 검토한다. 임시 권한을 앱과 확장에 동일하게 적용해야 하며 `isPro`를 유료 구매처럼 기록하면 안 된다. 기존 24시간 체험 및 StoreKit 체험과의 중복 정책을 먼저 정한다. 만료 시 자동화는 중지해도 기록·초안·기본 기능은 유지한다. 이 실험의 구매 효과를 확인하기 전 가격과 체험 기간을 동시에 바꾸지 않는다.

앱 오픈 광고는 현재보다 더 늘리지 않는다. 첫 3일 또는 첫 실제 완료 전 노출 억제, 빠른 입력 진입 제외, 로딩 대기 축소를 **별도 실험**한다. 채택 기준은 광고 수익 감소를 포함한 다운로드당 총수익금과 7일 재사용 개선이다. 현재 8초는 최대 대기값이며 모든 사용자가 실제 8초를 기다린다는 뜻은 아니다.

## 6 누적 1000건의 수치 계획

현재 전체 기간 누적 IAP를 `N0`라 하면 남은 목표는 `max(0, 1000 − N0)`다. 첨부 38건을 `N0`로 확정할 수 없으므로 아래는 **38건이 누적이라는 예시**다. 이 경우 962건이 남는다.

확정하지 않은 갱신과 기존 무료 사용자의 전환을 미리 더하지 않고, 신규 다운로드에서 발생하는 첫 유료 구매만으로 필요한 규모를 계산한다.

| 신규 다운로드의 35일 내 첫 유료 전환 가정 | 추가 962건에 필요한 신규 다운로드 |
| --- | ---: |
| 3.28% | 약 29,330 |
| 5% | 19,240 |
| 7% | 약 13,743 |
| 10% | 9,620 |

3.28%는 첨부 지표를 신규 유입에 적용한 참고 시나리오다. **5~7%는 실험 목표이며 업계 평균이나 예상 실적이 아니다.** 목표를 35일 코호트로 평가하므로 마지막 다운로드 이후 최대 35일의 관찰 시간이 추가된다. 실제 유입의 국가와 목적이 달라지면 전환율도 달라진다.

같은 962건을 첫 구매만으로 만들 때, 월 1,000 다운로드·5% 전환이면 월평균 50건으로 약 20개 월 유입분이 필요하다. 월 2,000·7%라면 140건으로 약 7개 월 유입분, 월 3,000·7%라면 210건으로 약 5개 월 유입분이다. 각각 마지막 코호트의 35일 관찰은 별도다. **816건을 현재 월 다운로드로 바꿔 계산하지 않았다.**

실제 목표 추적에서는 월별 신규 유료 구매 + 기존 무료 사용자의 첫 구매 + 구독 갱신 + 기존 고객의 추가 구매를 중복 없이 더한다. 무료 체험 시작·복원은 별도 열에 두고, App Store Connect IAP와 실제 과금 거래의 차이를 설명한다. 환불은 별도 지표와 순과금 건수로 관리한다. 작은 월 결제를 늘려 목표 숫자만 달성하는 대신 수익금도 증가해야 한다.

## 7 유입을 늘리는 방법

**첫 유입 확대는 이미 발생한 봉우리의 재현부터 시작한다.** App Store Connect에서 날짜·국가·소스·상품별 다운로드와 구매를 분해해 효과가 있었던 유입 경로를 찾는다. 상품 페이지 조회 증가와 구매 증가가 같은 유입에서 발생했는지 확인한다.

| 실행 | 보여줄 내용 | 평가 기준 |
| --- | --- | --- |
| 스토어 첫 3장 개선 | 잠금화면에서 할 일 완료 → 목적에 맞는 자동 전환 → 실제 유료 결과 | 스토어 다운로드 전환과 해당 유입의 D35 첫 유료 전환 |
| 업무용 소개 영상 | 기존 미리알림 연결 → 오늘 할 일 표시 → 완료 반영 | 캠페인별 첫 유료 구매 / 다운로드 |
| 공부용 소개 영상 | 현재 구현된 D-Day와 공부 할 일 사용. 목표 연결 출시 후 연결 장면 추가 | 동일 기준, 미구현 기능은 광고하지 않음 |
| 목적별 스토어 페이지 | 업무와 공부를 각각 설명하고 앱에서 같은 목적의 설정으로 연결 | 페이지별 다운로드당 수익금 |
| 기존 다른 앱의 선택형 소개 | 생산성 관련 앱의 설정·추천 영역에 실제 시연 링크 | 소개 경로별 설치와 첫 유료 전환 |

처음에는 업무·공부 두 목적만 비교하고 국가도 실제 유료 구매가 나온 상위 국가부터 집중한다. 광고비 집행은 측정한 고객 획득 비용이 보수적인 순수익 기여보다 작을 때 확대한다. 현재 US$87만으로 광고 예산의 손익 한도를 정할 수 없다.
