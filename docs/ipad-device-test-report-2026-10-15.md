# iPad 실기기 무료·Pro 테스트 결과

2026-10-15 / Asia/Seoul

## 결과

연결된 **iPad Air 11형(M2), iPadOS 26.6.2**에 서명된 Debug 앱과 위젯 확장을 설치해 테스트했다. 아래 **9개 시나리오는 수정·재검증 후 각각 최종 통과**했다. 하나의 실행에서 처음부터 모두 통과한 결과라는 뜻은 아니며, 최초 실패와 수정 후 통과 로그를 함께 보관했다.

Pro는 사용자가 허용한 Debug 전용 구독 상태 대체로 검증했다. 실제 카드 결제나 App Store 구독 구매는 하지 않았다. 임시 Pro 분기와 QA 화면은 `#if DEBUG` 안에 있고 Release에는 포함되지 않는다. QA 모드에서는 실제 구매 호출도 차단한다.

## 발견하여 수정한 문제

1. **iPad 키보드가 저장 버튼을 가림:** 고정 높이 입력 패널 때문에 텍스트는 입력되지만 저장 버튼 탭이 키보드 영역에 들어갔다. 입력 중 패널 높이를 줄이고 키보드 표시 완료 시 입력 영역 전체를 스크롤해 저장 버튼을 노출했다. 빈 입력에서도 키보드 툴바의 Done으로 닫을 수 있게 했다.
2. **설정에서 ‘오늘’로 돌아갈 수 없음:** 설정 화면에서도 이전 ‘오늘’ 세그먼트가 선택된 값으로 남아 탭해도 상태가 바뀌지 않았다. 설정 화면에서는 콘텐츠 세그먼트를 미선택 상태로 두어 오늘·캘린더 이동이 동작하도록 수정했다. 수정 후 미리알림 가져오기→오늘에서 완료→설정에서 원본 확인 경로가 통과했다.
3. **위젯의 최소 OS 버전 검사 누락:** iOS 16.1 대상 위젯에서 iOS 16.2 이상 전용 공통 함수를 무조건 호출해 실기기용 빌드가 실패했다. 사용 가능 버전 분기를 추가해 앱·확장 빌드를 통과시켰다.
4. **완료 버튼 접근성:** 할 일 완료 버튼에 명시적인 제목과 안정적인 식별자를 제공해 VoiceOver와 UI 자동화에서 구별되도록 했다.
5. 기존 Analytics 테스트의 오래된 호출 인자를 현재 API에 맞췄다. 해당 테스트 전체의 런타임 통과까지 주장하지는 않는다.

일부 실패는 테스트 조작 문제도 있었다. iPad 스위치는 실제 스위치 위치를 탭하도록 바꾸었고, 반복 설정 전에는 시스템의 Hide keyboard를 사용했다. `daily QA Daily`처럼 제목에 반복 토큰이 다시 들어간 모호한 테스트 문장은 단일 반복 토큰과 일반 제목을 사용하도록 바꿨다. 파서의 보수적인 원문 보존 정책은 변경하지 않았다.

## 광고·결제의 의미

무료에서는 Google 공식 **테스트 광고**가 실제 배너에 표시되고 `ad_impression_observed` 콜백이 발생했다. 광고 클릭은 하지 않았다. Pro에서는 광고 자격이 false이고 배너가 나타나지 않는 것을 확인했다.

**현재 Release의 광고는 `AdPolicy.isEnabled == false`이며, 테스트 광고 노출 성공이 배포 수익 발생을 의미하지 않는다.** 배포 광고 활성화, 실제 AdMob 광고 단위·앱 설정, 실제 구독 구매·갱신·복원·환불은 이번 테스트에서 검증하지 않았다.

## 확인 범위의 한계

- 시간 전환 검사는 앱이 실행 중인 상태에서 약 179초 동안 실제 시각을 기다렸다. 별도로 알림센터에서 OS가 렌더링하는 Live Activity 내용을 확인했다.
- **앱 종료·강제 종료·OS 중단 상태에서 정각에 Live Activity가 전환되는 것은 보장하지 않는다.** 백그라운드 실행은 iOS가 결정한다. 원격 APNs 갱신 서버는 구현하지 않았다. [Apple ActivityKit 설명](https://developer.apple.com/documentation/ActivityKit)
- 잠금화면/홈 화면의 독립 WidgetKit 위젯을 추가한 뒤 장시간 타임라인 전환까지 관찰한 테스트는 하지 않았다. 위젯 확장 실기기 빌드와 실제 Live Activity 표시는 확인했다.
- 단축어 앱에서 동작 생성·실행, 모든 언어·화면 방향·접근성 크기, 며칠·몇 주를 기다린 반복 생성, 전체 기존 테스트 모음은 이번 실기기 검사에 포함하지 않았다.

QA 모드에서는 Firebase Analytics 수집과 앱 이벤트 전송을 끄도록 보완했다. 이 조치를 넣기 전 초기 진단 실행의 GA4 반영 여부는 확인하지 않았으므로, 해당 시간대 통계에는 테스트 사용이 포함될 수 있다. 서버 측 분석 이벤트 삭제는 수행하지 않았다.

## 데이터 정리 및 복원

테스트 전에 앱 그룹의 기본 설정과 카드·구성·전환 규칙 파일을 기기 내 백업에 저장했다. 이후 QA 전용 데이터로 검사하고, 마지막에 백업을 복원했다.

QA 전용 EventKit 목록은 기록된 식별자와 QA 이름 접두어를 확인해 삭제했다. 원래 Apple 미리알림 목록은 삭제하지 않았다. 임시 Pro 캐시·QA 할 일·QA 구성·QA 전환 규칙·기기 내 QA 백업/미리알림 기록 파일이 남아 있지 않은 것을 확인했다. 복원 후 카드 2개가 있으며 QA 문자열이나 `device_qa_debug` 구독 값은 없다. [정리 확인 결과](device-qa-2026-10-15/restoration-check.json)

마지막으로 **QA 실행 인자 없이 앱을 다시 실행**했다. 현재 iPad에는 수정된 Debug 앱이 설치되어 있고 임시 Pro 강제 지정은 해제되어 있다. 미리알림 접근 권한은 테스트 중 허용된 상태이다.
