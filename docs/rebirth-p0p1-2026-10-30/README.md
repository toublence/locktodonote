# LockTodoNote P0·P1 개발 결과

2026-10-30 · 검증 빌드 1.2.1 (21)

승인된 [최소 변경 설계](../user-value-rebirth-audit/rebirth-design/06-revised-minimal-design.md)를 기준으로 구현했다. 기존 디자인·탭·색상·인라인 입력·템플릿 위치를 유지했다. 전면 개편 시안, 먼저 표시 3개, 우선순위·전역 정렬·새 작성창은 구현하지 않았다. App Store에 배포하지 않았다.

**기록용 메모가 표시를 바꾸는 부작용과 핵심 흐름의 광고·자동 제안은 줄였다. 다만 무료 기본 표시에서 중요한 일이 밀리는 문제까지 해결한 업데이트는 아니다. 실제 iPhone과 실제 구매 권리 복원은 출시 전 확인이 필요하다.**

## 1. 실제 변경과 이유

| 범위 | 변경 | 사용자 가치 |
| --- | --- | --- |
| P0 작성 유형 | 할 일/메모 선택은 입력 유형만 변경. 기존 템플릿을 명시적으로 고르면 표시 변경 | 메모를 쓰려다 할 일 카드가 바뀌는 사고 방지 |
| P0 메모 | 기존 ‘잠금화면에 표시’ 토글 재사용. 할 일 표시 중 기록은 기본 끔, 메모/혼합 표시의 빠른 교체는 기본 켬. 개별 메모 규칙에서는 임의 편입 차단 | 기록과 표시 교체를 구분하면서 교체 저장 1회 유지 |
| P0 표시 투영 | 기록용 메모는 기록에 남기고 잠금화면 후보에서 제외. 규칙이 명시 선택한 메모는 그 규칙 안에서 표시 | 토글을 껐는데 혼합 카드에 나오는 실제 검증 중 발견한 문제 수정 |
| P0 광고·제안 | 현재 앱 오픈 광고 중단. 완료 후 자동 리뷰·미리알림 제안·체험 종료 자동 결제 화면 차단 | 작성·완료·복귀에 끼어드는 화면 감소. 수동 설정·구매 진입은 유지 |
| P1 자동 전환 | 구성 없으면 기존 구성 저장 화면으로 이동하고 성공 시 원래 위치로 복귀. 범위·수용량 설명 추가 | 저장 위치를 찾아 헤매는 과정 감소 |
| P1 완료 취소 | 오늘의 기존 완료 그룹을 노출 | 캘린더로 이동하지 않고 완료 취소 가능 |
| P1 온보딩·설정 | 첫 시작 성공 뒤 오늘로 이동 선택, 단축어 버튼의 실제 동작·유지 시간·기기 내 저장 안내 정정 | 추가 교육 강제 없이 사용 시작, 잘못된 기대 감소 |
| 재현된 신뢰성 문제 | D-Day 미리보기는 전용 메모 사용. 사진 교체 시 공유 이미지 보존, 구성 저장은 누락된 비활성 사진 참조만 제외 | 보이는 메모와 저장 결과 일치, 유효한 사진 구성 저장 복구 |

사진의 활성 이미지가 실제로 없으면 기존 오류 처리를 유지한다. 이미 과거에 삭제된 이미지 자체를 복원하는 기능은 아니다. 반복 삭제·날짜 변경·위젯 갱신 엔진의 이전 완료 작업은 다시 구현하지 않았다.

## 2. 변경 전후 이용 흐름

| 의도 | 이전 | 이번 빌드 |
| --- | --- | --- |
| 할 일 입력·완료 | 기존 인라인 입력 → 저장 / 체크 | 같은 위치·동작. 별도 적용 단계 없음 |
| 할 일 표시를 유지하며 메모 기록 | 메모 유형 선택으로 표시 설정도 바뀔 수 있음 | 메모 유형 → 입력 → 저장. 기존 할 일 표시 유지 |
| 표시 중 메모 수정 | 기존 메모 편집 → 저장 | 같은 경로, 저장 즉시 내용 갱신 |
| 메모를 바로 교체 | 메모 입력 → 저장 | 메모/혼합 표시에서는 같은 저장 1회. 토글로 결과를 확인 가능 |
| 작성 유형을 이용해 표시 자체 변경 | 유형 선택과 표시 변경 결합 | 유형 선택 후 기존 템플릿 선택 필요. 이 의도에서는 명시적 선택이 추가됨 |
| 첫 자동 전환 구성 | 구성 없으면 저장 위치를 별도로 찾아야 함 | 기존 저장 화면 바로가기 → 저장 → 원래 위치 복귀 |
| 첫 할 일 표시 성공 | 후속 교육 진행 | 기존 교육 또는 오늘로 이동 선택 |
| 완료 취소 | 완료 항목을 찾기 위해 캘린더 이동 가능 | 오늘의 완료 그룹 펼치기 → 취소 |

화면의 실제 변경은 메모 입력의 작은 토글·안내, 완료 그룹, 기존 저장 화면 연결, 온보딩 버튼·문구에 한정했다. [작성 화면](evidence/05-memo-capture-preserves-todos.png), [저장 후 복귀](evidence/13-layout-save-return.png), [정리 후 무료 사용자 화면](evidence/16-clean-free-user.png)은 실제 시뮬레이터 화면이다.

## 3. 기존 기능·유료 권리 보존

정상 서명된 구버전 → 새 버전 설치에서 카드 16개, 구성 2개, 규칙 1개의 JSON과 관련 설정 23개를 비교했다. 구매 캐시는 JSON 키 순서만 달랐고 논리 값은 같았다. **이 구매 상태는 DEBUG 모의 Pro이므로 실제 고객의 StoreKit 권리 보존 증거로 대체하지 않는다.** 상품·가격·권리 판정·구매 복원 경계와 데이터 스키마를 새로 설계하지 않았다.

기존 규칙의 선택·시간·구성을 유지했다. 규칙 내 메모 표시는 저장된 전역 선택을 덮어쓰지 않고 표시용 사본으로 처리한다. 단축어의 명시적 추가·교체 정책은 앱 입력 기본값과 분리해 유지했다. 기존 사용자 변경 사항은 초기 차이와 분리해 보존했고, 전체 변경을 이번 작업으로 간주하거나 일괄 되돌리지 않았다.

## 4. 실제 사용 검증

시뮬레이터에서 직접 입력·완료·메모 교체·구성 저장·자동 전환 선택·미리알림 원본 완료·잠금화면 완료를 확인했다. 앱 테스트 20개, 공유 패키지 테스트 35개가 통과했고 최종 서명 빌드가 성공했다. 세부 조건과 한계는 [사용 검증 기록](01-user-validation.md), 수치는 [검증 요약](verification.json), 보존 비교는 [보존 결과](preservation.json)에 있다.

## 5. 남은 사용자 불편

- 미완료 30개에서 기본 최신순 카드에는 오래된 중요한 일이 밀릴 수 있다. 기존 규칙으로 선택한 2개는 유지됐지만, 선택 개수가 수용량을 넘으면 모두 표시되지는 않는다. 무료 기본 표시의 문제를 해결했다고 홍보하면 안 된다.
- 유형 탭을 표시 전환으로 쓰던 사용자는 기존 템플릿 선택을 한 번 더 해야 한다. 기록 중 부작용 감소와 이 조작 증가를 실제 기존 사용자에게 함께 확인해야 한다.
- 자동 전환이 활성화되면 기본 설정 수정과 현재 표시 결과가 다를 수 있는 기존 구조는 남는다. 시간 경계·장기 반복·실기기 표면별 결과는 추가 검증이 필요하다.
- 앱 오픈 광고는 현재 안전한 노출 구간 구분이 없어 전체 중단했다. 실제 광고 감소분과 Pro 실수익·앱 밖 완료를 같은 30일 창에서 비교해야 한다. 영구 수익 정책으로 확정한 것은 아니다.

## 6. 출시 전 판단

[출시 전 체크리스트](02-release-checklist.md)의 실제 iPhone·실제 구매 복원·시간 경계 항목을 확인해야 한다. 이 결과는 개발 및 시뮬레이터 검증 완료 보고이며 출시 승인이나 실제 고객 사용성 검증 완료를 의미하지 않는다.

기존 사용자라면 기록·메모 교체·완료·복귀의 방해는 줄어드는 방향이다. 중요한 일이 항상 보이는 앱, 또는 장기 유지율이 좋아진 앱이라고 단정할 근거는 아직 없다.
