# LockTodoNote 사용자 시나리오 평가

2026년 10월 30일. iPhone 13 mini·iPhone 17 Pro Max 시뮬레이터의 1.2.0 빌드 20을 직접 사용했다. 세부 행동과 화면은 [U16~U43 기록](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/06-continuation-evidence.md)에 연결된다. 소수 항목과 누적 상황을 재현했으며 수개월의 장기 이용이나 실제 iPhone 검증은 아니다.

## 처음 설치한 사용자

새 설치에서 소개→첫 할 일 ‘퇴근길 우유 사기’ 작성→Live Activity 시작→준비 완료→빠른 추가 안내까지 진행했다. 입력한 것이 잠금화면에 나온다는 목적은 이해하기 쉽다. 온보딩의 결과가 기능 설명에 머물지 않고 실제 기록과 표시로 이어진다는 점이 좋다. 도구 대기와 환경 복구가 섞였으므로 첫 1분·5분 내 도달 여부를 시간으로 판정하지 않는다.

‘빠른 추가 설정하기’는 단축어 앱을 열었다. ‘LockTodoNote에 추가’를 직접 실행해 Pack umbrella를 입력했고 앱에도 저장됐다. 하지만 버튼을 누르면 잠금화면·액션 버튼 설정까지 끝날 것이라는 기대와는 거리가 있다. 배치는 별도 작업이다. Siri 음성 입력과 실제 액션 버튼은 검증하지 않았다.

오늘 화면은 미리보기가 커서 결과를 바로 이해할 수 있다. 동시에 LIVE 시간, 반영, 템플릿, 단축어, 작성 모드와 고급 반복도 보여 이해할 대상이 많다. 위젯 미설치 상태에서 설치 완료를 눌렀을 때는 ‘아직 찾지 못했다’고 안내했다. 설치 여부를 잘못 확신시키지 않은 점은 좋다.

## 매일 사용하는 사용자

### 빠르게 적고 다음 날 준비하기

우유 사기·내일 오후 3시 병원 예약·매일 물 마시기를 한국어 여러 줄로 저장했다. 날짜·시각·반복 해석을 저장 전에 보여 주고 오늘과 내일의 목록을 구분했다. 반복 항목은 내일 캘린더에도 나타났다. 수동 날짜 선택과 재입력을 줄이는 실용적인 흐름이다. 실제 다음 날 발생까지 기다린 검증은 아니다.

예약 편집창에는 제목·반복·삭제가 보였지만 날짜·시각 변경 입력은 찾지 못했다. 빠르게 작성한 뒤 일정이 바뀔 때의 발견 가능성은 아쉽다. 다른 경로를 포함해 날짜 변경이 불가능하다고 단정하지 않는다.

### 메모와 할 일을 함께 다루기

짧은 준비물 메모는 저장·날짜별 조회가 자연스럽다. 다만 작성 탭을 메모로 바꾸자 잠금화면 미리보기도 메모 중심으로 바뀌었다. 사용자는 글 종류만 선택했다고 생각할 수 있다. 기록 삭제는 아니지만 기존 할 일이 표시에서 사라져 당황할 가능성이 있다.

Pro 혼합 템플릿에서는 실제로 메모와 할 일이 함께 보였다. Boarding pass and charger는 카드에서 짧게 생략됐다. 짧은 지침에는 적합하지만 긴 메모를 읽는 도구로는 맞지 않는다.

### 앱 밖에서 확인하고 끝내기

**핵심 경험은 성공했다.** 화면을 켠 시스템 잠금화면에서 Pack umbrella를 체크하자 앱을 열지 않고 카드에서 사라졌고, 캘린더에 완료 기록이 남았다. 저장 진단도 live_activity 완료 출처를 표시했다. 실제 홈 화면 중간 위젯을 설치하고 우유 사기를 완료했을 때도 앱을 열지 않고 ‘할 일 없음’으로 바뀌었고 widget 출처가 기록됐다.

iPhone 17 Pro Max에서는 Dynamic Island의 남은 개수 3을 길게 눌러 펼친 뒤 우유 사기를 완료했다. 홈 화면에 머문 채 개수가 2로 줄고 홈 위젯에서도 같은 항목이 빠졌다. 앱을 열지 않고 목적을 끝낸 것을 성공으로 평가한다.

초기 잠금 상태가 불명확했던 탭 한 번은 앱 복귀·테스트 광고로 이어졌으나, 이를 완료 기능 실패로 확정하면 안 된다. 후속 실제 성공과 구분했다. 잠금화면 직사각형·한 줄 accessory 위젯은 사용자화 갤러리에 도달했지만 목록 탐색을 완료하지 못해 설치 성공을 확인하지 못했다. 홈 위젯 성공과 혼동하지 않는다.

### 광고와 완료 취소

앱에서 완료한 항목은 오늘 목록에서 빠졌다. 캘린더에서 체크를 다시 눌러 취소할 수 있었지만 당장 실수를 되돌리려면 동선이 길었다. 현재 소스의 완료 그룹이 실행본의 기본 화면에서 실제 노출됐다고 간주하지 않는다.

단축어에서 돌아오는 흐름 등에서 Google 테스트 전면 광고 뒤 아침·저녁 알림 제안이 나타났다. 짧은 기록·확인 흐름의 중단은 실제로 경험했다. 운영 광고 빈도나 모든 앱 밖 완료에서 광고가 나온다고 주장하지 않는다. 광고를 클릭하거나 거래하지 않았다.

## 기록이 쌓인 사용자

일반 할 일 12개·완료 2개·메모 1개를 실제 UI로 누적했다. 새 항목이 먼저 나오고 카드 최대 5개에서 먼저 적은 Send proposal 등이 밀렸다. 이후 반복 Water plants를 추가해 미완료는 13개가 됐다. 살펴본 편집창에서 중요도·순서 지정은 발견하지 못했다.

적게 적을 때의 강점이 많이 적을 때는 한계가 된다. ‘최근 적은 일’과 ‘지금 중요한 일’은 다르다. 전환 규칙의 개별 선택으로 해결할 수는 있었지만 사용자가 별도로 구성과 규칙을 관리해야 했다. 수개월 기록·수천 항목의 검색과 성능은 검증하지 않았다.

Work 구성을 먼저 저장하고 평일 09~18시 Work hours 규칙을 만든 뒤 Water plants와 Read report만 골랐다. 현재 카드가 두 항목으로 좁혀지고 전체 기록은 남아 있었다. 실질적인 집중 가치가 있다. 처음 규칙을 만들 때는 ‘구성을 먼저 저장’ 안내로 돌아가야 했다. 앱 종료 상태의 정확한 시각 전환이나 매번 새 항목을 추가할 때의 장기 부담은 남은 확인 사항이다.

## 무료와 Pro 사용자

무료로 작성·날짜 인식·매일 반복 미리보기·앱 밖 완료까지 경험했다. 핵심 목적을 맛보기 위한 실제 흐름이 존재한다. Pro 모의 권한은 새 테스트 설치본에만 적용했고 결제하지 않았다.

매 3일 반복을 저장해 자동화 목록의 규칙과 다음 날짜를 확인했다. 요일 조합·월말 요일·격주는 선택지까지만 확인했다. 미리알림은 실제 EventKit QA 목록의 테스트 항목을 가져와 앱에서 완료하고 원본 완료를 확인했다. 일반 연결 해제·재연결도 사용했다. QA 버튼이 테스트 목록 준비·연결 일부를 대신했으므로 일반 사용자의 첫 연동 전체 난이도를 측정한 것은 아니다. 개인 미리알림과 다른 기기 iCloud 동기화는 건드리지 않았다.

날짜 템플릿은 큰 날짜와 다섯 할 일, 사진 템플릿은 선택한 꽃 사진과 할 일을 보여줬다. 저장한 Work를 다시 적용하면 혼합 템플릿으로 돌아갔다. 다음 두 결과는 별도 문제 기록이다.

- D-Day 부산 여행/10월 31일은 D-1로 표시됐지만, 편집에서 저장한 Charger and tickets가 카드 미리보기에는 ‘오늘 메모가 없어요’로 표시됐다. 시스템 D-Day 카드 전체에서도 유실된다고 일반화하지 않는다.
- 사진은 적용됐지만 Personal 구성 저장에서 ‘구성의 사진을 읽을 수 없습니다. 사진을 다시 선택하세요.’ 오류가 나 재사용 흐름이 막혔다. 원인 분석과 수정은 하지 않았다.

무료의 잠긴 D-Day에서도 구매 전 제목을 Busan trip으로 바꾸자 미리보기가 갱신되고 목적별 결제 안내에 이어졌다. 무엇을 얻는지 이해시키는 좋은 흐름이다. 일반 Pro 화면은 꾸미기가 먼저라 실용적인 자동화·연동의 지속 가치가 상대적으로 약하게 전달됐다.

시뮬레이터에는 연간 $4.99·월간 $0.99·펼친 평생 $9.99와 7일 체험 안내가 보였다. 운영 지역별 가격·자격 검증은 아니다. 앱 내 24시간 체험은 템플릿 범위로, StoreKit 7일 제안과 별개다. 구매·복원·체험 결제는 하지 않았고 테스트 종료 후 모의 Pro 인수 없이 실행했다.

## 잠금화면에 대한 답

| 질문 | 평가 |
| --- | --- |
| 앱을 열지 않아도 가치가 있는가 | 있다. 확인뿐 아니라 세 경로에서 완료와 반영을 확인했다 |
| 정보는 도움이 되는가 | 오늘의 짧은 소수 항목에는 유용. 누적 시 중요한 항목 선택이 관건 |
| 읽기 쉬운가 | 시뮬레이터에서 짧은 한국어 항목은 이해 가능. 실제 거리·밝기·큰 글씨는 미검증 |
| 작성·수정은 자연스러운가 | 여러 줄·날짜 인식은 좋다. 날짜 수정 경로와 작성 모드의 표시 변경은 혼동 가능 |
| 관리 부담은 어떤가 | 소수 항목은 낮다. 자동화 구성 선저장과 개별 선택은 단계가 많다 |
| 기본 미리알림과 다른가 | 큰 카드·메모·상황별 표시 조합. 완료 버튼만의 독점 차별점은 아니다 |
| 내일도 필요한가 | 반복 일과 미리 적은 일이 있다면 그렇다. 매일 앱을 열 필요는 없다 |
| 삭제하면 아쉬운 것은 | 잠금화면에서 다시 생각나고 바로 끝내는 흐름 |

기본 미리알림도 위젯 완료를 제공한다는 비교 기준은 [Apple 공식 안내](https://support.apple.com/en-euro/guide/iphone/iphcd5c65ccf/26/ios/26)에 근거한다. 같은 조건의 경쟁 앱 직접 비교 실험은 아니다.
