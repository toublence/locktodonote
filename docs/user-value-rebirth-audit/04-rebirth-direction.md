# LockTodoNote 재탄생 방향 제안

2026년 10월 30일. 제안의 중심은 **오늘 필요한 소수의 일을 잠금화면에서 보고 행동할 수 있도록 하며, 매일 관리해야 하는 부담을 줄이는 것**이다. 이번에는 개발하지 않는다. 새 기능보다 기존 기능의 실제 완결성을 먼저 평가한다.

## 우선순위

| 순서 | 제안 | 사용자 관점의 근거 | 판단에 필요한 결과 |
| --- | --- | --- | --- |
| 1 | 중요한 항목의 표시 선택을 쉽게 하기 | 12개 누적 시 최신 항목이 카드 최대 5개를 차지하며 오래된 일이 밀림 | 사용자가 지금 중요한 일을 표시하고 새 항목마다 규칙을 손보지 않아야 함 |
| 2 | 작성 유형과 표시 선택의 관계 개선 | 메모를 쓰려다 미리보기에서 할 일이 빠지는 경험 | 작성 후 표시 결과를 예측할 수 있어야 함 |
| 3 | 초기 설정과 앱 진입 중단 줄이기 | 구성 선저장 요구·단축어 별도 배치, 복귀 시 테스트 광고와 제안 | 첫 결과까지 연결하고 빠른 입력의 목적을 마칠 수 있어야 함 |
| 4 | 유료 결과의 신뢰도와 실용 가치 전달 | 사진 구성 저장 오류·D-Day 메모 미리보기 불일치. 자동화·연동은 실제 실용 가치 확인 | 보인 결과를 저장·재사용하고 줄어드는 수고를 이해해야 함 |
| 5 | 날짜·시간 수정과 완료 취소의 발견 가능성 개선 | 예약 편집에서 날짜 입력을 찾기 어렵고 취소는 캘린더로 이동 | 일상의 변경과 실수를 짧은 동선으로 처리할 수 있어야 함 |

앱 밖 완료는 Live Activity·홈 위젯·Dynamic Island에서 성공했다. 기존 핵심을 보호하는 방향이며 완료 기능이 실패했다는 전제로 개발을 재개하지 않는다. 발견한 결과 불일치는 별도 관찰로 남기고 원인 분석·수정을 수행하지 않았다. 이전 1단계 수정 작업도 다시 시작하지 않는다.

## 재탄생의 대상 사용자

우선 검증할 대상은 ‘해야 할 일은 적어 두지만 다시 열어 보지 않아 잊는 사람’이다. 오늘의 소수 항목과 준비 지침을 잠금화면에서 자주 보는 것이 실제 누락을 줄이면 설치 이유가 명확해진다.

기존 미리알림을 꾸준히 쓰는 사람에게는 대체보다 표시·행동의 보조 역할이 더 자연스러울 수 있다. 현재 연동은 제목·날짜·반복·삭제 전체를 자유롭게 양방향 편집하는 앱으로 설명하면 안 된다.

복잡한 프로젝트 관리, 긴 글 지식 관리, 공동 작업을 원하는 사람에게까지 맞추려 하면 핵심이 흐려질 수 있다. 이번 평가에서는 이런 사용자를 위해 기능 수를 늘릴 근거를 찾지 못했다.

## 개선 효과를 판단할 기준

사용자가 설정 설명 없이 첫 할 일을 표시하고, 다음 날 중요한 항목을 다시 보고, 앱 밖에서 목적을 마칠 수 있는지 확인한다. 반복 항목·표시 규칙을 계속 손보는 시간이 줄어야 한다. 앱 실행 D7만 늘고 표시 복구나 광고를 거치는 시간이 늘었다면 성공으로 보지 않는다.

광고 조정, 결제 문구, 체험 변경의 효과는 충분한 실제 이용과 수익 자료로 확인해야 한다. 이번 시뮬레이터의 소수 시나리오만으로 리텐션·매출 상승을 확정하지 않는다.
