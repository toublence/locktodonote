# LockTodoNote 사용자 평가 증거와 검증 범위

평가일은 2026년 10월 30일 KST다. 이 문서는 직접 사용한 결과와 코드에서만 확인한 동작을 구분한다. 앱의 코드나 구매 권리는 변경하지 않았다.

## 실행 환경

- 직접 사용 기기: `LockTodoNote Review Fix QA`, iPhone 17 Pro Max, iOS 26.1 시뮬레이터.
- 실행 바이너리: 기존 평가용 기기에 설치되어 있던 LockTodoNote 1.2.0 빌드 20. 설정 화면에서도 버전을 직접 확인했다. 실행 파일 수정 시각은 2026년 10월 28일 10:48:41 KST다. App Store 배포본과의 동일성은 확인하지 않았다.
- 현재 작업 디렉터리에 기존 미커밋 변경이 있다. 이번에는 재빌드하지 않았다. 따라서 소스에서 발견한 기능과 실행 바이너리의 기능을 동일하다고 가정하지 않는다.
- 구체적인 차이: 실행 앱의 캘린더에서는 하단 빠른 입력을 직접 보았지만, 현재 `CalendarTabView.swift`의 본문은 월 달력과 선택일 목록으로 구성되어 있다.
- 기존 QA 항목 `Keep this task`는 변경하지 않았다. 이번에 작성한 테스트 항목과 메모는 해당 시뮬레이터에 남겨 두었다. 실제 사용자 기기의 자료를 사용하지 않았다.
- `Steady Release Compact`에는 같은 기존 빌드를 새로 설치했다. 초기 검은 화면 이후 환경을 복구하여 신규 온보딩·무료·Pro 주요 흐름을 사용했다. 추가 U16~U43는 [후속 기록](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/06-continuation-evidence.md)에 별도 정리했다. Steady 앱과 그 자료는 변경하지 않았다.

## 실행을 막은 환경 문제

처음 평가용 시뮬레이터를 열었을 때 macOS는 다음 경고를 표시했다.

> You can’t save the file “091CDD1E-C47F-45FE-8EBE-101705FC4F8C” because the volume “Macintosh HD” is out of space.

당시 읽기 전용 용량 확인에서 약 299MiB가 남아 있었다. 이후 약 6.8GiB로 표시되는 시점에 기존 평가용 기기를 부팅하고 위 흐름을 직접 사용했다. 다음 확인에서는 약 272MiB가 남았고, 화면 제어 도구는 화면 읽기와 연결 갱신에서도 이미지 생성 오류를 반환했다. 여유 공간 변동의 원인은 조사하지 않았으며 앱의 저장 용량 문제로 돌리지 않는다. 사용자 파일이나 개발 캐시를 삭제하지 않았다.

공간 확보 후에는 화면 제어가 한 차례 복구되어 U10~U15를 진행했다. 이후 여유 공간이 약 8.5GiB로 표시되는 상태에서도 Simulator 조회가 `timeoutReached`로 반복 실패했다. 화면 제어 세션 재연결과 초기화로 해결되지 않아 Simulator 창 재실행을 시도했다. 이후 Simulator 앞단을 종료·재실행하여 복구하고 후속 평가를 진행했다. 이 응답 문제를 앱 자체의 오류나 사용자 가치 부족으로 집계하지 않는다. PC 재부팅 전의 관찰과 캡처가 보존되어 보고서 정리를 이어갔으며 재부팅 후 재실행 검증을 했다고 주장하지 않는다.

## 최종 검증 범위와 남은 항목

신규 온보딩·앱 내 완료/캘린더 취소·잠금화면/홈 위젯/Island 완료·단축어 추가·12개 누적·Pro 모의 주요 기능은 U16~U43에서 추가 확인했다. U09·U12의 초기 실패나 미확인 상태가 최종 기능 판정은 아니다. 후속 성공과 함께 해석해야 한다.

아래는 여전히 미검증이다. 조사되지 않은 기능을 통과로 표시하지 않는다.

- 실제 iPhone·iPad의 가독성·조작성. 다른 iPad Simulator가 전면에 있던 캡처는 제품 증거에서 제외.
- 잠금화면 직사각형·한 줄 accessory 위젯의 실제 설치·갱신. 홈 위젯과 구분.
- 실제 자정·시간대 변경·긴 백그라운드·Live Activity 만료와 만료 후 복귀. 자동 전환의 정확한 시각 경계.
- 첫 1분·5분 도달 시간, 수개월·수천 항목의 장기 이용과 성능.
- 기본 평일·매주와 고급 요일 조합·월말·격주의 실제 발생. N일 반복은 설정까지 확인.
- 일반 삭제·반복 삭제의 각 범위, 제목 수정 저장, 날짜 고정·오늘 복귀, 구성 덮어쓰기·삭제의 전체 흐름.
- 실제 예약 알림 수신, Siri 음성·액션 버튼·잠금화면 단축어 배치, 공유 확장·저장 링크 회수.
- VoiceOver·큰 글씨·전체 프라이버시 모드의 시스템 화면·10개 언어 전체 품질.
- StoreKit 구매·복원·만료·체험 자격·운영 가격, 운영 광고 빈도·수익, 개인 미리알림과 다른 기기의 iCloud 반영.
- 실제 D1·D7 유지율과 30일 수익. 기존 수익 자료의 선택 기간은 불명확.

실제 구매 없이 새 테스트 설치본의 DEBUG 인수로만 Pro를 모의 적용했다. 테스트 후 일반 무료 실행으로 돌렸고 템플릿 24시간 안내를 확인했다. 상세 권한과 데이터 범위는 후속 기록의 실행 환경에 명시했다. 재빌드·설치 의존성 변경·앱 코드 수정은 하지 않았다.

## 참고 자료의 범위

기존 [10월 28일 수정 보고서](/Users/nam/projects/ios/locktodonote/docs/review-fix-report-2026-10-28.md)는 삭제·날짜·위젯에 대한 과거 QA 기록이다. 그 기록을 이번 직접 테스트의 통과로 옮기지 않는다. 기존 [잠금화면 이미지](/Users/nam/projects/ios/locktodonote/docs/review-fix-qa-2026-10-28/review-system-live-activity-after-delete.png)는 달력과 할 일, 시스템 Live Activity 허용 안내가 함께 보이는 과거 시뮬레이터 캡처로만 참고했다.

기존 [수익 모델](/Users/nam/projects/ios/locktodonote/docs/iap-1000-model-2026-10-28.json)의 수치는 과거 자료의 전사값이다. 현재 계정의 수익이나 유지율을 새로 조회한 결과가 아니다.

경쟁 기준은 10월 30일 열람한 [Apple의 잠금화면 사용 안내](https://support.apple.com/en-euro/guide/iphone/iphcd5c65ccf/26/ios/26)다. 미리알림 위젯에서도 항목 완료가 가능하다고 설명하므로, 잠금화면에서 완료할 수 있다는 사실 하나를 LockTodoNote만의 차별점으로 삼을 수 없다. 이번에 미리알림 앱과 나란히 조작한 비교 실험은 수행하지 않았다.
