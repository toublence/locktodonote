# 핵심 사용자 경험과 표시 규칙

> 재검토 반영 · 기존 디자인 유지가 우선이다. 이 문서는 원안 기록이며, 충돌하는 개발 범위·화면·정책은 [최소 변경 설계](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/06-revised-minimal-design.md)로 대체한다. ‘먼저 표시 3개’·화면 재배치·새 공통 작성창·전역 적용·기본 정렬 변경은 확정 개발 대상에서 제외했다.

## 하루의 경험

아침에는 오늘의 반복 할 일과 예정한 일이 준비되어 있다. 사용자는 중요한 일이 있으면 ‘먼저 표시’를 선택한다. 새 할 일을 적어도 선택한 일은 앞에 남는다. 휴대폰을 켤 때 확인하고 체크하면 앱을 열지 않고 완료된다. 완료한 자리는 다음 항목이 채운다. 메모를 적는 행동은 이 표시 순서를 바꾸지 않는다.

기존 미리알림을 쓰는 사람은 원본 목록을 유지한 채 필요한 목록만 연결한다. 업무·개인 화면을 번갈아 쓰는 사람은 기존 시간 전환으로 범위를 바꾼다. 단순한 사용자에게 연결·시간 규칙·알림 설정을 요구하지 않는다. 목표는 매일 실행 횟수를 늘리는 것이 아니라 기억 부담과 관리 시간을 줄이는 것이다.

## 중요한 항목을 유지하는 구조

### 표시 대상과 순서를 분리한다

‘저장한 전체 기록’, ‘현재 상황에서 표시할 수 있는 항목’, ‘현재 화면에 실제로 보이는 항목’을 구분한다. 30개를 저장해도 카드에 30개를 넣지 않는다. 오늘 화면에는 전체 미완료를 남기고 잠금화면에는 필요한 앞부분만 보인다.

표시 결정 순서는 다음과 같다.

1. 현재 표시 날짜를 결정한다. 기본은 오늘이며 기존 날짜 고정 기능은 명시적으로 선택했을 때만 적용한다.
2. 해당 날짜의 미완료를 기존 반복·이월 결과에서 가져온다. 미래 날짜의 항목을 ‘먼저 표시’했다는 이유로 오늘로 옮기지 않는다.
3. 적용 중인 시간 규칙이 있으면 기존의 전체/개별 시리즈·메모 필터를 적용한다. 범위 밖의 개인 항목이 중요하다는 이유로 업무 화면에 끼어들지 않는다.
4. 범위 안에서 ‘먼저 표시’한 항목을 사용자 순서대로 앞에 둔다.
5. 나머지는 시각이 있는 항목을 예정 시각 오름차순으로, 시각 없는 항목을 오래된 입력순으로 채운다. 시각 그룹 안에서는 과거 시각도 원래 시각순을 유지한다. 동일 시각·입력 시각이면 안정적인 항목 식별 순서를 사용한다.
6. 프라이버시 모드에 맞게 본문·제목·개수를 가린 후 각 표시 면의 수용량만 보여준다. 저장·전달되는 표시 내용에도 같은 보호를 적용한다.

현재 구현에 같은 순서 규칙이 이미 있다면 재사용한다. 제안된 정렬은 새로운 우선순위 점수나 긴급도 추론을 추가하지 않는다. 사용자가 직접 선택한 순서가 자동 정렬보다 우선한다.

### 먼저 표시

한 기본 표시 설정에서 최대 3개를 선택한다. ‘중요도 상·중·하’와 별도 마감 체계를 만들지 않고 **잠금화면의 앞자리에 두는 동작**으로 한정한다. 무료에서도 제공한다. 기본값은 0개다. 단순한 사용자는 선택하지 않아도 날짜·시각과 오래된 항목 기준으로 표시된다.

| 동작 | 결정된 결과 |
| --- | --- |
| 오늘 목록 행의 ‘먼저 표시’ 선택 | 빈 자리에 추가. 목록의 ‘먼저 표시’ 그룹과 미리보기에 즉시 반영 |
| 이미 3개 선택한 상태에서 추가 | “먼저 표시할 일 3개가 선택돼 있어요”와 교체 목록 표시. 자동으로 기존 항목을 빼지 않음. 취소하면 그대로 |
| 순서 편집 | 드래그와 ‘위로/아래로’ 버튼 모두 제공. 완료 체크 영역과 별도 조작 |
| 선택 해제 | 데이터·일정은 그대로, 일반 자동 정렬 위치로 돌아감 |
| 완료 | 현재 발생분을 제외하고 다음 항목으로 채움. 완료 취소는 기존 선택 순서로 복귀할 수 있도록 선택 이력을 함께 복구. 중복 완료 요청은 한 완료로 취급 |
| 일반 할 일의 선택 지속 | 완료·삭제·선택 해제까지. 미완료 이월도 항목의 정체성을 유지하면 지속. ‘중요하므로 날짜를 바꿈’은 하지 않음 |
| 반복 항목 선택 | 기본은 ‘이번 할 일만’. 사용자가 ‘반복할 때마다’를 명시적으로 선택하면 기존 반복 시리즈 식별을 기준으로 향후 발생분에 적용 |
| 반복의 이번 분 완료 | 이번만 선택은 해제. 매번 선택은 다음 발생일까지 비활성 상태로 남음. 다음 발생 때 같은 순서로 돌아옴 |
| 미래 또는 다음 발생까지 비활성 선택 | 3개 자리 중 선택 자리는 유지하지만 오늘 카드 공간은 점유하지 않음. 편집 목록에는 “내일 다시 표시” 등 상태를 보여 직접 교체 가능 |
| 삭제·연결 해제로 대상이 없어짐 | 무효 선택을 정리하고 일반 항목으로 채움. 원본 기록을 새로 생성하거나 삭제하지 않음 |

‘이번만’과 ‘반복할 때마다’는 기존 반복 편집의 범위 선택 방식과 어휘를 재사용한다. 전체 반복 자료를 복제하지 않는다. 미리알림 항목은 원본 식별과 연동되는 표시용 선택만 저장하며 원본 중요도나 일정은 변경하지 않는다. 원본 식별을 안정적으로 유지할 수 없는 경우에는 잘못된 다른 항목에 선택을 붙이지 않고 해제 상태를 알린다.

### 화면이 작을 때의 계약

현재 스냅샷의 최대 5개 제한을 늘리는 것을 해결책으로 삼지 않는다. 기본 Live Activity는 기존 공간 안에서 최대 5개, 홈 중간 위젯은 기존 최대 3개를 기준으로 한다. 큰 글씨·템플릿에 따라 더 적을 수 있다. 잠금화면 한 줄·직사각형 위젯은 같은 정렬의 선두 항목을 용량에 맞게 표시한다. 세 개를 선택해도 모든 표시 면에서 세 개가 보인다고 설명하지 않는다.

제안 화면의 요약은 “표시 3 / 남은 13”처럼 현재 미완료 기준이다. ‘전체 저장 수’, ‘현재 범위 미완료 수’, ‘실제 표시 수’를 섞지 않는다. 자동 전환의 전체 필터 밖 항목은 현재 범위 개수에서 제외하고 앱에서 “전체 오늘 13 · 업무 범위 2”로 구분한다. 개수만·숨김 모드에서는 기존 프라이버시 계약을 우선하며 노출될 수 있는 추가 개수도 사전 확인한다.

| 예시 | 기대 결과 |
| --- | --- |
| 먼저 표시 2개 + 일반 11개에서 새 할 일 10개 입력 | 선택 2개 순서 유지. 나머지 자리만 자동 정렬. 전체 목록에는 모두 남음 |
| 선택 3개, 홈 위젯 용량 3 | 세 개 모두 우선 표시. 하나 완료하면 일반 후보 선두가 빈 자리를 채움 |
| 선택 3개, 한 줄 위젯 용량 1 | 첫 번째만 표시. 완료 후 두 번째가 선두. 셋 모두 보인다는 안내 금지 |
| 업무 규칙에 선택 2개만 포함, 전역 선택은 개인 일 | 업무 2개만 표시. 개인 선택의 유출이나 빈 공간을 이유로 범위 확장하지 않음 |
| 규칙이 명시적인 항목 없음 선택 | “이 구성에 표시할 일이 없어요.” 전체 오늘에 일이 있다는 사실은 앱 안에서만 안내. 기본 전체로 자동 복귀하지 않음 |
| 모든 현재 후보 완료 | “지금 표시할 일을 모두 마쳤어요.” 새로운 입력·결제를 강요하지 않음 |
| 고정 날짜가 내일 | ‘내일’ 표시를 유지. 오늘 화면의 기록 날짜와 혼동되지 않게 표시. 자동 전환이 날짜를 바꾸는 경우 적용 전 차이를 보여줌 |

사진·메모·D-Day 중심 레이아웃은 수용량이 다르다. 할 일 영역이 없는 레이아웃에서도 표시 선택은 보존하되 “이 템플릿에는 할 일이 표시되지 않아요”라고 미리 알린다. 기존 템플릿을 몰래 할 일형으로 바꾸지 않는다.

### 기존 기능으로 해결하는 부분과 신규 범위

| 요구 | 기존 기능 활용 | 충분하지 않은 부분과 최소 신규 동작 |
| --- | --- | --- |
| 업무에는 업무 일만 보기 | 기존 시간 규칙의 개별 시리즈·메모 선택 | 필터와 선택 화면을 재사용. 별도 업무 프로젝트·태그 불필요 |
| 선택한 일이 다음 반복에도 포함 | 기존 반복 시리즈 식별 | 표시 우선 선택을 시리즈에 연결하는 작은 확장 필요 |
| 기본 무료 화면에서 중요한 일을 먼저 유지 | 기존 메모 고정과 규칙 선택 UI의 표현 재사용 | 규칙은 Pro·시간·구성에 묶여 있고 선택 순서를 표현하지 않음. Card의 고정값은 checklist 개별 항목 순서와 같다고 볼 수 없음. 무료 기본 순서 선택이 필요 |
| 새 항목이 늘어도 자동화 규칙을 매번 수정하지 않기 | 기존 ‘전체’ 필터 | 새 규칙은 전체를 기본값으로 유지. 특정 목록 자동 분류·AI 추천은 추가하지 않음 |
| 여러 화면의 결과 일치 | 기존 공통 표시 스냅샷과 완료 경로 | 동일 대상·정렬 규칙을 공통 사용하도록 계약을 보강. 별도 위젯 데이터 관리 기능 불필요 |

자료 검토상 기존 `SmartLockScreenRule`의 항목 선택은 범위 필터이며 순서 배열로 동작하지 않는다. 구현 단계에서 동등한 선택 기능이 다른 경로에 있다면 새 저장 체계 대신 그 기능을 노출한다. 사용자의 기존 선택·규칙·구매를 옮기거나 지우는 전제는 없다.

## 작성과 표시의 역할

작성은 제목·본문·날짜·반복·저장 여부만 바꾼다. 표시 설정은 템플릿·표시 내용·메모 선택·날짜 고정·범위·프라이버시를 바꾼다. 입력 탭, 최근 입력 유형, 단축어 기본 입력 대상은 표시 설정을 변경하지 않는다.

메모 저장 후 “메모를 저장했어요 · 표시에 사용”을 제공한다. ‘표시에 사용’을 선택할 때만 기존 메모 선택과 템플릿 화면을 열고 바뀔 결과를 보여준다. 혼합 템플릿이 Pro이면 그 선택 시점에만 혜택 안내를 제공한다. 저장 자체를 결제 안내로 막지 않으며, 취소하면 원래 카드와 저장 메모가 모두 유지된다. 무료의 기존 메모형 표시 경로도 유지한다.

오늘 화면의 할 일·메모 필터는 조회만 바꾼다. 잠금화면 설정에서 ‘할 일/메모/둘 다’를 바꾸는 것은 명시적인 적용 동작이다. 새 설정 화면을 연 상태에서 뒤로 가면 초안만 버리고 마지막 적용 설정을 유지한다.

## 처음부터 다음 주까지

첫 실행에서는 첫 기록과 표시 시작을 우선한다. 단축어 배치·알림 시간·사진·자동화는 첫 성공 이후 사용자가 관련 기능을 원할 때 안내한다. Live Activity 시작 요청 성공과 실제 잠금화면을 사용자가 확인한 상태는 구분한다.

다음 날에는 기존 반복과 예정 항목이 후보가 되고 완료한 전날 항목은 일반 미완료처럼 다시 나타나지 않아야 한다. 반복 생성·이월 로직은 기존 것을 사용한다. 새 설계 때문에 이전 날짜 전환·반복 삭제 수정 작업을 재작성하지 않는다.

시간 전환은 ‘언제→무엇을→미리보기→저장’ 흐름 안에서 기존 구성을 만들거나 선택하게 한다. 새 구성을 자동으로 확정 저장하지 않고 최종 저장 시 규칙과 함께 확정한다. 취소하면 임시 구성은 남기지 않는다. 겹치는 시간 제한과 야간 규칙의 기존 의미를 유지한다.

## 호환성과 실패 시 기준

기존 사용자는 현재 템플릿·표시 유형·날짜·연결·시간 규칙·구성·권리를 그대로 시작한다. 기본 정렬의 변경은 첫 업그레이드에서 “새 항목이 중요한 일을 밀지 않도록 표시 순서를 바꿀 수 있어요”와 결과 미리보기로 제안한다. 사용자가 적용하기 전에는 기존 자동 순서를 유지한다. 신규 사용자는 제안 정렬을 기본으로 한다. 순서 정책은 다시 변경할 수 있어야 한다.

새 표시 선택을 저장하지 못하면 기존 순서로 돌아가고 저장 실패를 알린다. 선택만 바꾸다 할 일 본문·완료·원본이 손상되는 상태는 허용하지 않는다. 기기·확장 간 업데이트 지연은 동기화 완료로 위장하지 않는다. 화면에서 관찰 가능한 범위의 상태만 안내하며, 표시를 복구하러 들어온 사용자를 광고나 구매 안내로 막지 않는다.
