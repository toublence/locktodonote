# 화면별 설계와 변경 전후 이용 흐름

> 재검토 반영 · 기존 디자인 유지가 우선이다. 이 문서는 원안 기록이며, 충돌하는 개발 범위·화면·정책은 [최소 변경 설계](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/06-revised-minimal-design.md)로 대체한다. ‘먼저 표시 3개’·화면 재배치·새 공통 작성창·전역 적용·기본 정렬 변경은 확정 개발 대상에서 제외했다.

[화면 변경안](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/screen-proposal.html)은 기존 실제 캡처와 새 화면 8개를 비교하는 정적 설계 보드다. 새 화면은 문구·정보 배치·조작 위치를 판단하기 위한 시안이며 실제 앱이나 작동하는 iOS 위젯이 아니다. 번호는 아래 화면과 일치한다.

## 전체 탐색 구조

기존 오늘·캘린더·자동화·설정의 역할을 유지한다. 다섯 번째 탭을 추가하지 않는다. 오늘 오른쪽 위 ‘잠금화면’을 누르면 표시 설정 화면으로 들어간다. 설정의 관련 항목도 같은 화면으로 연결한다.

| 위치 | 주요 역할 | 옮기거나 접는 정보 |
| --- | --- | --- |
| 오늘 | 미완료 확인·먼저 표시 선택·작성·완료·취소 | 템플릿 가로 목록과 장시간 LIVE 상세를 잠금화면 화면으로 이동 |
| 캘린더 | 과거·미래 조회, 특정 날짜의 작성·편집 | 조회만으로 표시 날짜를 바꾸지 않음. 날짜 고정은 별도 버튼 |
| 자동화 | 반복 목록·미리알림 연결·시간 전환 | 각 기능은 기존 상세 화면을 활용. 처음에는 이용 중 기능부터 표시 |
| 설정 | 가독성·프라이버시·구매·데이터·언어·지원 | App Group 같은 구현 용어를 사용자에게 필요한 저장 범위 설명으로 바꿈 |
| 잠금화면 상세 | 표시 내용·순서·템플릿·상태·설치·구성 | 작성 입력창을 두지 않음. ‘작성’은 오늘 화면이나 공통 작성창으로 이동 |

## 변경 전후 핵심 흐름

| 상황 | 조사에서 확인한 기존 흐름 | 제안 흐름 | 사용자가 판단할 차이 |
| --- | --- | --- | --- |
| 처음 사용 | 소개→첫 입력→표시 시작→완료→빠른 추가 교육 | 첫 입력→‘저장하고 잠금화면에 표시’→시스템 허용 필요 시 안내→결과 확인→오늘 | 첫 기록 전에 꾸미기·연결·단축어 선택을 요구하지 않음 |
| 누적 13개에서 중요한 일 유지 | 최근 입력 우선→오래된 일 밀림→시간 규칙·개별 선택으로 조절 가능 | 행의 ‘먼저 표시’→공통 선두 유지→앱 밖 완료→다음 항목 채움 | 구성을 만들지 않고 일상 목록에서 조절 |
| 메모 작성 | 메모 입력 탭→미리보기도 메모형으로 변경→저장 | 작성창의 메모→저장→기존 할 일 카드 유지. 원할 때 ‘표시에 사용’ | 글을 남기다가 표시가 바뀌지 않음 |
| 자동 전환 첫 설정 | 규칙 추가→구성 선저장 안내→이전 화면으로 이동→다시 규칙 | 언제→현재 구성 사용/기존 구성 선택→필요시 그 자리에서 편집→표시 범위→저장 | 되돌아가 별도 준비할 단계 감소 |
| 미리알림 이용자 | Pro 안내→권한·연결, QA에서는 준비를 일부 대신함 | 원본 유지·완료 반영 설명→샘플 결과→사용자가 연결 선택→구매 필요 시 안내→권한·목록→실제 결과 | 결제 전에 결과 이해. 개인 목록 접근은 명시적 연결 이후 |
| 단축어로 입력 후 복귀 | 추가 성공→앱 복귀에서 테스트 전면 광고와 알림 제안 | 추가 성공 응답→필요할 때 앱 복귀→추가된 항목 바로 확인 | 외부 빠른 기록이 끝까지 빠름 |
| 앱 밖 완료 | 실제 Live Activity·홈 위젯·Island에서 성공 | 같은 경로를 유지하고 공통 표시 순서·후속 항목 반영 | 성공한 기능을 재개발하지 않고 예측 가능성 강화 |

## S01 첫 기록과 첫 표시

상단은 “오늘 잊고 싶지 않은 일은 무엇인가요?”와 짧은 실제 카드 예시다. 바로 입력할 수 있으며 기본은 할 일이다. 보조 선택 ‘메모부터 작성’과 ‘나중에’는 유지한다. 다중 페이지 기능 소개·가격·템플릿 목록을 첫 입력 앞에 배치하지 않는다.

입력 아래에는 자연어 인식 결과를 기존 방식으로 보여준다. 예: ‘내일 오후 3시 병원 예약’ → ‘내일 · 오후 3시’. 기본 날짜와 인식 결과를 수정할 수 있고 해제도 가능해야 한다. 첫 행동 버튼은 **‘저장하고 잠금화면에 표시’**다. 작성과 표시를 함께 한다는 것을 이 한정된 첫 실행 동작에서는 명시한다. 일상 작성 버튼은 단순 ‘저장’이다.

| 상태 | 화면과 다음 행동 |
| --- | --- |
| 빈 입력 | 예시 힌트, 버튼 비활성. 임의의 샘플을 사용자 기록으로 저장하지 않음 |
| 저장 성공·시작 요청 성공 | 앱 미리보기와 “잠금화면을 켜서 확인해 보세요”. ‘확인했어요’ 또는 ‘아직 안 보여요’. 실제 시스템 화면을 보았다고 자동 확정하지 않음 |
| 사용자가 첫 표시 확인 | 오늘로 이동. 이후 선택 안내는 오늘의 작은 카드 하나로만 표시 |
| 앱이 표시 시작 상태를 확인했지만 사용자 미확인 | “표시를 시작했어요”까지만 안내. 확인 대기 상태를 보존 |
| 시작 불가·허용 거부 | “할 일은 저장됐어요. 잠금화면 표시는 아직 설정되지 않았어요.” 설정 확인·기존 위젯 설치 안내·나중에 선택 |
| 저장 실패 | 입력 보존·재시도. 표시 성공으로 진행하지 않음 |
| 미래 항목만 입력 | “내일 할 일로 저장했어요. 오늘 표시할 일은 아직 없어요.” 날짜를 오늘로 바꾸는 선택과 그대로 두기. 자동 날짜 변경 금지 |
| 건너뛰기 | 오늘 빈 상태로 이동. ‘첫 할 일 적기’와 ‘잠금화면 설정’으로 재진입 |

첫 표시 뒤에 알림·단축어·위젯 설치를 연속 팝업으로 띄우지 않는다. 사용자가 ‘더 편하게 쓰기’를 펼치면 홈/잠금 위젯과 빠른 추가를 각각 선택한다. 목표는 일반적인 허용 상태에서 첫 결과를 1분 안에 경험하게 하는 것이며, 측정 전 성능 주장으로 사용하지 않는다.

## S02 오늘

상단 제목은 ‘오늘’, 오른쪽은 ‘잠금화면’. 다음 줄에 상태를 짧게 표시한다. 예: ‘Live Activity 시작됨 · 표시 설정’. 기존 약 8시간 정보는 상세에 둔다. 갱신 지연·종료·설치 확인 필요가 있으면 해당 정보가 정상 상태보다 우선한다.

미리보기는 펼치기 전에는 2행 요약이고 전체 카드는 잠금화면 화면에서 본다. 이어서 ‘먼저 표시 2/3’, ‘나머지 할 일 11’, ‘완료 2’ 그룹이 나온다. 전체 목록은 표시 범위에 의해 숨겨지지 않는다. 자동 전환 중에는 ‘지금 업무 구성 · 표시 2 · 오늘 전체 13’과 범위 설명을 함께 제공한다.

행의 왼쪽은 완료 체크, 본문 탭은 편집, 오른쪽은 ‘먼저 표시/해제’다. 스와이프와 더보기에서도 같은 동작을 제공하고 색상만으로 구분하지 않는다. 선택 순서 편집은 그룹의 ‘순서 변경’에서 한다. 선택이 3개인 경우 교체 시트를 제공한다.

하단의 ‘할 일 추가’가 주 동작이고 메모는 공통 작성창에서 유형을 선택한다. 큰 글씨·작은 화면에서도 주 동작을 가리지 않도록 목록은 스크롤하고 키보드가 나타나면 작성 버튼과 입력 영역이 보인다.

완료 후 짧은 ‘완료했어요 · 되돌리기’를 제공한다. 읽는 데 시간이 필요한 접근성 사용자는 사라지는 알림에만 의존하지 않고 접힌 ‘완료’ 그룹에서 다시 취소할 수 있다. 기존 소스에 완료 그룹이 있으므로 노출과 동선 개선으로 처리하고 새로운 완료 기록 체계를 만들지 않는다. 앱 밖 완료 직후 자동 앱 열기나 토스트를 위해 앱을 전면화하지 않는다.

## S03 공통 작성과 편집

작성창 상단에 ‘할 일 | 메모’를 둔다. 전환은 입력 초안에만 영향을 준다. 유형별 초안은 창 안에서 보존하되 저장하지 않은 초안의 장기 보관 기능은 추가하지 않는다. 닫기 시 입력이 있으면 기존 취소 확인 방식으로 보존 또는 폐기를 선택한다.

| 유형 | 기본 필드 | 보조 필드와 결과 |
| --- | --- | --- |
| 할 일 작성 | 본문·날짜·시각 | 기존 인식 결과·반복. 고급 반복은 기존 Pro 선택. 표시 유형은 자동 변경하지 않음 |
| 메모 작성 | 본문 | ‘저장한 메모는 표시 설정에서 선택할 수 있어요.’ 저장 시 기존 표시 메모를 자동 교체하지 않음 |
| 할 일 편집 | 제목·날짜·시각·반복 | 날짜/시각을 찾기 쉬운 위치에 노출. 기존 수정 기능이 있다면 연결하고 없으면 최소 보강으로 범위를 확정 |
| 반복 편집 | 기존 범위 선택 | ‘이번만/앞으로/전체’의 기존 의미 유지. 이전 반복 삭제 수정 로직 재작성 제외 |
| 연결된 미리알림 | 제목·시각·연결 출처 | 지원되는 완료만 앱에서 처리. 원본 편집 항목에는 ‘미리알림에서 수정’ 안내. 임의의 양방향 편집 추가 제외 |

메모 저장 후의 ‘표시에 사용’은 선택 사항이며, 누르면 S04에서 기존 표시와 새 표시를 비교한다. 무료가 혼합 템플릿을 선택할 때만 Pro 안내가 나오며, 닫아도 작성한 메모와 기존 할 일 표시는 그대로다. 메모만 표시하는 기존 무료 경로도 제공한다.

## S04 잠금화면 설정

위에서부터 실제 적용 상태, 현재 구성 미리보기, 표시 내용과 순서, 템플릿, 글자·프라이버시, 지속 표시 방법으로 배치한다. 주요 버튼은 ‘변경 적용’이다. 들어와서 구경하거나 입력창 유형을 바꾸는 것으로 적용하지 않는다.

| 영역 | 내용과 동작 |
| --- | --- |
| 현재 상태 | 오늘/고정 날짜, 기본/시간 규칙 이름, 마지막 앱 처리 시각. 시스템에서 실제로 보였다는 뜻으로 표시하지 않음 |
| 표시 내용 | 할 일·메모·둘 다와 현재 권한. 미지원 조합은 결과와 이유를 먼저 설명 |
| 먼저 표시 | 오늘 화면과 같은 선택/순서 편집. 별도의 중복 선택 목록을 만들지 않음 |
| 메모 선택 | 저장한 메모 중 현재 표시 1개를 기존 기능으로 선택. D-Day 준비 메모와 구분 |
| 템플릿 | 기존 달력·혼합·날짜·사진·D-Day. 모든 결과를 먼저 보고 적용은 명시적으로 선택 |
| 날짜 | 오늘 자동 표시/선택 날짜 고정. 캘린더 조회와 별개임을 안내 |
| 가독성과 프라이버시 | 글자 크기·굵기·모드·숨김/개수. 변경 전후 결과를 미리보기로 확인 |
| 구성 | 기존 저장·적용·덮어쓰기·삭제. 바뀌는 것은 표시 설정이며 기록 삭제가 아님을 명시 |
| 계속 보기 | Live Activity 상세·기존 잠금/홈 위젯 안내. 설치·갱신을 앱이 확인 가능한 범위까지만 말함 |

시간 규칙이 적용 중일 때는 ‘현재 업무 구성을 편집’과 ‘기본 표시 설정’을 구분한다. 임시 수동 우선권·일시 정지 타이머 같은 신규 전환 기능은 추가하지 않는다. ‘기본으로 보기’를 고르면 자동 전환 전체를 끈다는 결과를 명시하고, 켜기 전까지 기본 설정을 사용한다. 자동 전환의 시간·범위는 S06에서 수정한다.

‘아직 안 보여요’에서는 허용 상태·종료 여부·위젯 설치 안내로 연결한다. App Group·payload·render 같은 구현 용어 대신 사용자가 할 수 있는 행동을 쓴다. 확실하지 않은 갱신 시각을 ‘현재 최신’이라고 표시하지 않는다.

## S05 잠금화면과 위젯

기존 Live Activity의 달력·할 일 구조 안에서 선두 순서를 반영한다. 선택 항목에는 작은 ‘먼저’ 표시를 줄 수 있지만 본문 공간과 접근성 읽기를 우선한다. 완료는 체크 버튼 한 번이며 그 이외 본문 탭은 기존 앱 진입 동작을 유지한다. 잘못 누르기 쉬운 장식이나 광고·구매 버튼을 넣지 않는다.

공간이 부족하면 후순위 행·장식부터 줄이고 중요한 첫 항목의 읽기와 체크 영역을 유지한다. 실제 표시 행 수는 기기·큰 글씨·템플릿으로 검증한다. 달력 크기 변경은 P2의 별도 비교로 두고 P0에서 새 템플릿을 만들지 않는다.

홈 중간 위젯과 Dynamic Island도 같은 선두 순서를 사용한다. 완료 저장과 다른 표면의 반영은 구분해 검증한다. 원본 반영이 늦는 미리알림 완료를 성공으로 단정하지 않으며 실패 시 재시도 가능한 앱 내 상태로 이어져야 한다. 시스템 제약 때문에 지연이 있으면 이 앱의 표시 정보가 최신인지 오해시키지 않는 표현이 필요하다.

프라이버시 개수만 모드에서는 본문 대신 개수만 제공하고, 항목을 특정하지 못하는 상태에서 임의의 항목을 완료시키는 버튼은 제공하지 않는다. 잠금·인증 조건에 따라 iOS가 요구하는 동작은 실기기에서 확인하며 우회하지 않는다.

## S06 자동화

상단에 ‘사용 중’ 기능과 다음 결과를 보여준다. 예: ‘물 주기 · 3일마다 · 다음 11월 2일’, ‘업무 · 평일 09:00–18:00 · 전체 중 2개’. 적용 중이지 않은 기능은 접힌 소개로 둔다.

시간 규칙 추가는 ‘언제’를 입력한 뒤 현재 구성 또는 저장 구성을 선택하고 필요하면 같은 흐름에서 구성 편집을 한다. 기존 선택 UI를 이용해 ‘전체 항목’ 또는 ‘직접 선택’을 정한다. 전체 항목을 기본으로 하여 새로 입력한 일이 자동으로 포함되게 한다. 직접 선택에는 ‘새 항목은 자동 포함되지 않아요’를 표시한다. 마지막 단계에서 범위·순서·다음 전환 미리보기 후 저장한다.

구성과 규칙은 마지막에 함께 확정되거나, 실패 시 기존 설정이 유지되어야 한다. 같은 이름·중복 시간·야간 범위·참조 구성 삭제는 기존 정책을 적용하고 결과를 설명한다. ‘이 규칙에 표시할 일이 없음’은 전체 일 없음과 구분한다. 정시 적용·다음 날 갱신은 실기기 검증 이후 지원 범위에 맞게 안내한다.

## S07 미리알림 연결

첫 화면의 설명은 “쓰던 미리알림을 다시 적지 않고 표시하세요. 완료하면 원본에도 반영됩니다.”다. 제목·날짜·반복·삭제의 원본 편집 범위도 바로 아래에 둔다. 내 데이터 없이 볼 수 있는 샘플 카드는 ‘예시’라고 표시한다.

명시적으로 연결을 선택하고 권한이 있을 때만 목록을 가져온다. Pro가 필요하면 권한 팝업보다 먼저 혜택 안내를 제공하고, 구매 없이 돌아갈 수 있다. 기존 권한·연결 API와 목록 선택 UI를 재사용한다. 구매 전 실제 개인 목록 접근을 추가하지 않는다.

연결 후에는 선택한 목록 이름·항목 수·마지막 성공 동기화·지금 동기화·연결 해제를 보여준다. 완료 원본 반영 대기/실패가 발생하면 별도 상태로 표시하고 재시도 경로를 제공한다. 연결 해제는 가져온 표시 복사본에 영향을 주며 원본은 남는다는 확인을 제공한다. 상태 확인을 위한 실행에는 광고를 금지한다.

## S08 Pro와 설정

일반 Pro 첫 문장은 “반복 입력과 화면 전환을 줄이세요”다. 연결·자동 전환·고급 반복을 먼저, 여러 구성·무제한 빠른 추가·사진·D-Day·색상·광고 제거를 다음에 둔다. 사용자가 템플릿에서 왔다면 이미 확인한 개인화 카드와 목적별 설명을 유지한다.

정확한 가격·기간·무료 체험 자격은 실제 스토어 결과로 표시한다. 이 설계 화면에는 조사 가격을 현재 판매 가격처럼 고정하지 않는다. 월간·연간·평생·복원·닫기를 찾을 수 있게 둔다. ‘템플릿 24시간 체험’과 ‘조건에 맞는 계정의 스토어 체험’을 별도로 설명한다. 새 자동화 체험권·새 상품은 P0에 만들지 않는다.

설정의 ‘동기화 및 데이터’는 ‘데이터 보관’으로 이해하기 쉽게 바꾸고, 실제 제공하는 기기 내 보관·공유 범위와 기기 교체 시 주의를 설명한다. 클라우드 백업이 있는 것처럼 표현하지 않는다. 언어·약관·개인정보·광고 선택·리뷰·버전·저장 경고는 유지한다.
