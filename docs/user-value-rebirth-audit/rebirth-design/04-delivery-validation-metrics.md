# 개발 우선순위와 실기기 검증 및 제품 지표

> 재검토 반영 · 기존 디자인 유지가 우선이다. 이 문서는 원안 기록이며, 충돌하는 개발 범위·화면·정책은 [최소 변경 설계](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/06-revised-minimal-design.md)로 대체한다. ‘먼저 표시 3개’·화면 재배치·새 공통 작성창·전역 적용·기본 정렬 변경은 확정 개발 대상에서 제외했다.

## 개발 범위와 진행 순서

다음은 향후 개발을 위한 순서다. 이번 작업은 문서와 화면안 작성으로 끝낸다. 기존 1단계의 반복 삭제·날짜 전환·위젯 갱신 수정 작업을 재개하지 않는다. 새 표시 선택·화면 분리로 영향을 받는 경로의 회귀 확인은 필요하지만 기존 동작을 재설계하는 과제로 확장하지 않는다.

| 우선순위 | 범위 | 선행 조건 | 완료 기준 |
| --- | --- | --- | --- |
| P0 1 | 배포 대상·기존 권리·표시 동작의 기준 확정 | 조사 바이너리와 현 소스의 차이 확인 | 정상 기준·기존 데이터/권리 보존 항목 확정. 새 빌드와 과거 조사 결과를 혼동하지 않음 |

| P1 4 | Pro 안내·템플릿 체험 구분·만료·복원·구성 재사용 | 신뢰성 문제 영향 확인 | 실제 결과를 보고 선택. 취소·만료에도 기록·기존 권리 보존 |
| P1 5 | 지속 표시·위젯 안내·언어/큰 글씨/VoiceOver | 실제 OS 동작 확인 | 지원 경로와 지연 한계 설명. 설치 미확인 상태를 성공으로 처리하지 않음 |
| P2 1 | 달력 공간·템플릿별 정보 비중 비교 | P0/P1 사용 결과 | 중요한 첫 항목의 가독성이 실제로 개선될 때만 조정 |
| P2 2 | 미리알림/자동화의 구매 전 체험 확대 여부 | 샘플 결과 설명과 결제 이탈 자료 | 설명 부족이 원인일 때만 최소 체험 설계. 신규 상품·권리 변경 자동 도입 제외 |
| P2 3 | 비차단 광고·링크 회수 동선·새 기능 필요성 | 유지·수익·실제 수요 자료 | 기존 기능 개선으로 부족한 이유가 확인될 때만 별도 설계 |

P0의 먼저 표시와 기본 화면 분리는 무료·Pro 공통이다. 미리알림과 자동 전환의 기존 작동은 유지하고 P1에서는 이용 흐름을 개선한다. P0에서 이 기능들을 제거하거나 재구현하지 않는다.

## 실제 iPhone 검증 계획

모든 항목은 **실행 전 시나리오**이며 통과 결과가 아니다. 배포 지원 하한 OS와 대표 최신 지원 OS, 작은 화면과 Dynamic Island 기기를 포함한다. 적어도 한 대의 실제 iPhone에서 기본 잠금 상태와 허용 상태를 사용자가 직접 확인한다. 위젯은 설치/갱신/완료를 각각 확인하고, 최소 한 번은 실제 자정을 넘기며 앱을 열지 않는다. 실제 결제 대신 승인된 테스트 구매 환경을 사용하고 개인 자료 대신 독립 QA 목록을 쓴다.

## 제품 지표의 정의

### 성공의 단위

주 지표는 **첫 표시 설정을 마친 사용자 중 최근 7일에 서로 다른 2일 이상 유효한 앱 밖 완료를 한 비율**로 제안한다. 분자는 Live Activity·홈/잠금 위젯·Island 등에서 완료가 저장된 서로 다른 사용자 수, 분모는 최초 표시 설정 후 최소 7일이 지나 관찰 가능한 사용자 수다. ‘표시 설정’은 앱의 시작/설치 확인 가능 상태이며 사용자가 실제로 읽었다는 뜻이 아니다. 사용자 ‘직접 확인했어요’ 응답은 별도 속성으로 나눈다.

이 지표는 읽기만 하는 메모 사용자와 주 1회 반복 사용자를 과소평가한다. 따라서 메모형/할 일형·반복 주기·신규/기존 사용자를 구분하고, 읽기 중심 사용자의 효용은 짧은 선택형 인터뷰로 보완한다. 불필요한 완료를 유도하지 않는다.

### 수집 계약

최소한 첫 저장·표시 시작/실패·사용자 표시 확인·중요 선택/변경·완료 요청/저장/원본 결과·표시 복구·광고 실제 노출·결제 결과가 필요하다. 기존 이벤트와 완료 출처가 있으면 우선 재사용한다. 새 이벤트 이름을 정했다는 이유로 이미 수집 가능한 것으로 간주하지 않는다.

완료 요청에는 중복을 제거할 요청 식별, 표면 출처, 발생 날짜와 로컬 시각, 해당 표시 버전, 결과와 실패 분류만 필요하다. 과업 본문·메모·사진·개인 목록 이름·원본 식별자를 분석 서버에 보내지 않는다. 분류에 필요한 연결 여부와 반복 종류만 최소 범주로 집계한다.

확장에서 분석 네트워크가 항상 실행된다고 전제하지 않는다. 허용된 저장 경로에 최소 결과를 남기고 안전하게 전달할 수 있는 시점에 전송하는 방식의 가능성을 검토한다. 앱을 열어야만 전송된다면 앱을 열지 않는 사용자 자료가 누락되므로 관측 가능 완료와 미수집 범위를 함께 표기한다. 분석 전송이 실패해도 완료 저장은 막지 않는다.

완료 요청과 재전송·재시도·위젯 갱신은 한 행동으로 중복 계산하지 않는다. 확정 실패와 아직 결과가 도착하지 않은 요청을 나누며 보고서에는 수집 마감 시각·지연 비율을 표시한다. 원시 내용이나 사용자 텍스트 없이도 주요 지표를 판단할 수 있어야 한다.

### 수익과 함께 보는 판정표

사업 목표는 **완료된 연속 30일의 광고 수익과 IAP 수익금 합계 $30 이상**, 즉 평균 하루 $1이다. IAP는 스토어 수수료·환불 반영 후 수익금, 광고는 광고 플랫폼 수익 기준으로 보고하되 확정/추정 여부를 구분한다. 통화·시간대·집계 기간과 환율 기준을 명시한다. 스토어 가격이나 무료 체험 시작 수를 수익으로 대체하지 않는다. 연간·평생 결제는 그 거래의 해당 기간 수익으로 한 번만 계산한다.

## 출시 판단 절차

먼저 동일 정의로 변경 전 기준을 기록하고 신규/기존·무료/Pro·표시 방식별로 나눈다. P0는 실기기의 핵심 시나리오를 통과한 뒤 제한된 배포에서 확인한다. 지표 관측 기능이나 표시 순서 기능을 중단해도 기존 기록·설정·권리가 유지되어야 한다.

전면 광고 0회·범위 밖 정보 노출 0회·선택 항목 밀림 0회·기록/권리 손실 0회는 보호 조건이다. 위반 시 확대를 중단한다. 실제 관측되지 않은 것을 ‘0회 발생’으로 보고하지 말고 검증/관측 범위를 함께 쓴다.

행동 지표는 최소 7일 관찰을 완료한 코호트로, 수익은 완결된 30일 창으로 본다. 충분한 표본이 없으면 분자·분모와 불확실성을 제시하고 방향성 관찰로만 판단한다. 광고 정책과 화면을 동시에 바꾼 결과를 특정 문구 하나의 효과로 단정하지 않는다. 분리 실험이 필요해도 핵심 흐름 광고 금지와 데이터 보호는 실험 대상에서 제외한다.
