# 기존 사용자 관점의 재탄생 설계 검토

2026년 10월 30일. **원안을 그대로 개발하는 것은 권하지 않는다.** 필요한 개선은 있지만, ‘먼저 표시 3개’, 새 설정 화면, 공통 작성창, 일괄 적용 방식은 기존 사용자의 조작과 학습을 늘릴 수 있다. 기존 디자인과 익숙한 빠른 작성·템플릿 전환을 유지하면서 실제 혼동과 중단만 줄이는 방향으로 축소한다.

이 검토는 앞선 시뮬레이터 실사용 U01~U43와 현 소스의 관련 동작을 대조한 결과다. 이번에 새 버전을 실행하거나 기존 사용자 인터뷰를 추가한 결과는 아니다. 실제 기기의 날짜 경과·자동 전환 경계·기존 구매자의 업그레이드 경험은 여전히 검증 대상이다. 보완 후 개발 기준은 [최소 변경 설계](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/06-revised-minimal-design.md)다.

## 구체적인 문제와 더 간단한 대안

### 먼저 표시 3개는 문제보다 큰 관리 체계를 만든다

U29에서 항목 12개가 누적되자 먼저 적은 Send proposal이 최대 5개 카드에서 밀렸다. 해결할 가치가 있는 문제다. U32에서는 기존 자동 전환의 선택으로 전체 13개 중 두 항목만 표시하는 데 성공했다. 따라서 ‘중요한 일을 남기려면 반드시 새 기능이 필요하다’는 결론은 과하다.

다만 기존 선택은 범위 필터다. `SmartLockScreenRule.filteredCards`는 선택된 시리즈만 남길 뿐 선택 배열의 순서로 정렬하지 않는다. 선택한 여섯 개 중 어느 것이 첫 번째여야 하는지는 해결하지 못한다. 무료 기본 표시에도 같은 선택 경로가 있다고 확인한 것은 아니다. **기존 선택만으로 모든 누적 상황이 해결됐다고 주장해서도 안 된다.**

원안은 범위 선택과 전역 우선 선택이라는 두 가지 설정을 만들었다. 업무 규칙에 없는 개인 일을 먼저 선택하면 보이지 않는 것이 개인정보 측면에서는 맞지만, 사용자는 ‘먼저 표시했는데 왜 안 보이나’라고 느낄 수 있다. 이 모순을 설명하려고 화면·그룹·배지를 더 추가하면 단순한 앱이 복잡해진다.

| 원안의 구체적 문제 | 기존 사용자에게 생기는 일 | 보완 |
| --- | --- | --- |
| 최대 3개라는 별도 한도 | 네 번째 선택에서 교체 창을 처리. 실제 Live Activity 5개와 다른 한도를 학습 | 3자리 한도·교체 창 철회. 화면의 실제 수용량과 선택 개수를 혼동하지 않게 안내 |
| 내일 반복이 비활성 자리 차지 | 오늘 한두 개밖에 없는데 새 항목을 우선 선택하지 못함 | 예약 자리·비활성 우선 항목이라는 개념 제거 |
| 이번만/반복할 때마다 우선 선택 | 기존 반복 범위 선택과 별개로 또 관리 | 기존 시리즈 필터를 그대로 사용. 별도 우선순위 범위 모델 보류 |
| 완료 뒤 선택 이력 복원 | 할 일 취소 외에 표시 우선 이력을 신경 써야 함 | 기존 완료/취소의 결과만 유지. 새 우선 이력 저장 기능 보류 |
| 시간 있는 일·오래된 일 우선으로 전역 정렬 변경 | 최신 입력이 바로 보이던 편리함 상실. 밀린 오래된 일이 계속 점유할 가능성 | 기존 순서 보존. 자동 정렬 정책 변경을 이번 개선에 묶지 않음 |
| 신규/기존 사용자에게 다른 정렬 | 같은 설명인데 서로 다른 결과. 사용자가 선택해야 할 설정 증가 | 새로운 정렬 모드·업그레이드 선택 팝업 도입 보류 |

대안은 현재 규칙의 ‘전체/직접 선택’ 기능을 계속 사용하고, 선택 항목이 적을 때 그 범위를 안정적으로 유지하는 것이다. 수용량보다 많으면 표시되지 않는 항목이 있다는 점을 기존 편집 화면의 설명으로 알린다. 기존 사용자의 선택 목록을 자동 축소하거나 새 할 일을 강제로 포함하지 않는다.

무료 기본 화면과 수용량 초과 상황은 해결되지 않은 요구로 남긴다. 실제 사용자 과제로 기존 선택을 써 보게 한 뒤에도 중요한 일을 유지할 수 없다면, 기존 항목 선택 화면 안의 선택적 순서 조정 하나를 검토한다. 그때도 새 전역 그룹·별표·3자리 한도·두 종류의 우선순위를 한꺼번에 도입하지 않는다. 이는 아직 확정된 개발 항목이 아니다.

### 작성과 표시를 분리하되 내용 갱신은 막지 않는다

U04에서 메모 작성 탭을 누르자 할 일 미리보기가 바뀌었다. 소스의 `setCaptureMode`도 입력 유형과 `selectedContentSection`을 함께 바꾸고 있다. 이 연결은 분리할 근거가 충분하다.

하지만 원안의 ‘모든 메모는 저장만 하고 나중에 설정에서 선택’은 기존 메모 이용자에게 불편하다. 현 소스의 `addMemo`는 기본적으로 새 메모를 표시 대상으로 선택하고, 메모 편집에는 이미 ‘잠금화면에 표시’ 토글이 있다. 원안은 이를 활용하기보다 별도 설정 화면으로 우회시켰다.

최소 원칙은 다음과 같다.

- 작성할 유형을 바꾸는 것만으로 표시 유형·템플릿·자동 전환을 바꾸지 않는다.
- 이미 표시 중인 메모를 수정해 저장하면 수정 내용이 반영된다. 별도 ‘적용’을 요구하지 않는다.
- 새 메모를 현재 표시 메모로 교체할지와 템플릿을 메모형으로 바꿀지는 다른 행동이다. 기존 표시 선택을 재사용하며 자동 전환의 개별 메모 목록까지 임의 수정하지 않는다.
- 메모를 빠르게 교체하던 사용자의 저장 경로는 유지한다. 저장 뒤 다른 화면을 열어 한 번 더 적용하는 단계를 기본으로 만들지 않는다.

새 메모의 선택 기본값은 현재 표시 문맥에 따라 보완할 필요가 있다. 기본 메모/혼합 표시를 쓰는 명시적 빠른 작성에서는 기존의 ‘저장하면 현재 메모 교체’를 유지한다. 할 일만 보는 상태에서 기록용 메모를 쓸 때는 기존 선택 메모를 유지하고 필요할 때 기존 표시 선택을 쓴다. 이 차이가 생기는 자리에는 짧은 결과 안내가 필요하다. 자동 전환이 새 메모를 범위에서 제외하면 선택만으로 보인다고 약속하지 않는다. 세부 조건은 최소 변경 설계에 명시했다.

### 첫 사용을 단순하게 만들기 위해 새 온보딩을 만들 필요는 없다

U16에서 기존 소개·첫 작성·표시 시작 흐름은 성공했다. 첫 입력 필드는 현 소스에서도 자동 포커스를 제공한다. 모든 소개를 없애거나 일상 작성창까지 새 시트로 바꿀 근거는 부족하다.

‘저장하고 잠금화면에 표시’를 한 버튼으로 합치면 시작 실패 뒤 재시도할 때 저장을 다시 하는지 모호해진다. 미래 날짜만 입력한 경우에도 같은 문구는 오늘 카드에 보일 것처럼 오해시킬 수 있다. 저장 성공과 시스템 시작 성공을 나누는 현재 구조를 유지하는 편이 안전하다.

U17의 실제 불편은 ‘빠른 추가 설정하기’가 단축어 앱만 열었다는 점이다. 버튼을 ‘단축어 앱 열기’처럼 실제 동작에 맞게 설명하고, 기존 나중에 선택을 찾기 쉽게 한다. 첫 성공 뒤 알림·교육·광고가 이어지지 않게 하는 것이 우선이다. ‘확인했어요’ 응답을 추가 필수 단계나 앱 진입 조건으로 만들지 않는다.

### 화면 이동과 일괄 적용은 기존의 직접 조작을 늦춘다

오늘 화면에서 템플릿 목록을 치우면 기존 사용자는 템플릿을 바꿀 때 새 화면으로 이동해야 한다. 큰 미리보기를 요약으로 바꾸면 실제 결과를 보려고 한 번 더 펼쳐야 한다. 인라인 작성을 공통 시트로 바꾸면 입력 시작 자체에 조작이 추가된다. 이런 변경은 유지하지 않는다.

또한 모든 가독성·프라이버시·템플릿 조절에 ‘변경 적용’을 붙이면 지금 보면서 조절하던 편리함을 잃는다. 사진 구성처럼 저장 자체가 필요한 동작과 단순 표시 조절은 다르다. 기존의 직접 적용·취소·저장 경계를 유지하고 혼동되는 특정 동작만 고친다.

### 자동 전환의 선저장 안내만 고치면 되는 곳에 큰 생성 흐름을 만들었다

U31의 문제는 구성 없이 규칙을 추가했을 때 이전 화면으로 돌아가 준비해야 했던 점이다. 새 단계별 작성 화면과 구성/규칙 공동 저장까지 반드시 필요하지는 않다.

구성이 없으면 기존 구성 저장 화면으로 바로 이동할 수 있는 안내를 제공하고, 저장 후 원래 규칙 화면으로 돌아오게 하는 것으로 먼저 해결한다. 기존 구성이 있으면 현재 규칙 편집 화면과 선택 목록을 그대로 쓴다. 기존 규칙을 ‘모든 항목’으로 초기화하지 않는다.

원안의 ‘기본으로 보기’가 자동 전환 전체를 끄는 것은 부작용이 크다. 기본 설정을 구경하거나 고치려다 매일 쓰던 업무/개인 전환을 멈출 수 있다. 자동 전환 끄기는 기존의 명시적 토글에만 맡긴다.

## 기존 유료 사용자에게 약속해야 할 것

| 기존 이용 | 그대로 유지할 것 | 변경하면 안 되는 예 |
| --- | --- | --- |
| 사진·D-Day·혼합 템플릿 | 외형·사용 권한·개인화 값·저장 구성 | 업데이트 때 기본 달력으로 일괄 복귀 |
| 시간 전환 | 켜짐 상태·요일·시각·구성 참조·개별 대상·규칙 밖 수동 설정 | 기본 설정 편집을 이유로 전체 끄기, 전체 항목으로 재설정 |
| 반복 | 주기·앵커·예외·종료·완료/취소 범위 | 새 표시 기능을 위해 시리즈 재생성 |
| 미리알림 | 기존 권한·선택 목록·원본 소유·완료 연동 | 재연결 강요, 원본을 다른 날짜로 이동하거나 삭제 |
| 빠른 메모 | 표시 중 내용 수정과 의도적인 메모 교체의 짧은 경로 | 모든 저장 뒤 새 설정 화면 필수 이동 |
| 구매·복원·광고 제거 | 기존 상품 권리와 복원·체험 범위 | 이미 구매한 기능을 별도 상품으로 다시 판매 |

설계에 ‘유지’라고 쓰는 것만으로 보존이 증명되지는 않는다. 실제 기존 설정을 가진 설치본의 업그레이드 전후 비교가 필요하다. 이번 검토에서는 이를 통과했다고 표시하지 않는다.

D-Day 저장 메모와 카드 미리보기의 불일치(U27), 사진 구성 저장 오류(U37)는 유료 결과 신뢰에 직접 영향을 준다. 재탄생을 위한 새 UI보다 영향 범위 확인이 먼저다. 이 항목은 별도 신뢰성 검증으로 유지하고, 이전 반복 삭제·날짜 전환·위젯 수정 작업을 다시 시작하지 않는다.

## 무료 Pro와 광고 판단

무료 작성·기본 반복·앱 밖 확인/완료를 유지하고, Pro는 기존 연동·고급 반복·자동 전환·개인화의 추가 편의를 제공하는 방향은 납득할 수 있다. 먼저 표시라는 미확정 기능을 무료 혜택으로 미리 약속하지 않는다. 기존 Pro의 자동화 범위를 무료로 바꾸거나 새로 제한하는 결정도 하지 않는다.

공통 Pro 안내의 실용적 설명을 보완하는 것은 좋지만, 사진·D-Day를 사러 온 사용자에게 매번 긴 자동화 설명을 거치게 하면 불편하다. 실제 성공한 목적별 개인화 미리보기(U42~U43)를 유지한다. 가격·상품·체험은 기존 조건과 실제 스토어 결과를 따른다.

핵심 입력·저장·완료·외부 복귀·오류 복구에서 광고와 연속 제안을 빼는 것은 사용자 관점에서 타당하다(U19). 그러나 테스트 광고 관찰로 전체 운영 빈도나 광고를 모두 없앤 뒤의 지속 수익까지 알 수는 없다. ‘핵심 흐름 금지’는 유지하고 ‘앱 전체 광고 영구 폐지 확정’으로 해석하지 않는다. 안전한 노출 구분이 안 되면 해당 전면 광고를 노출하지 않는 것이 기본이다. 새로운 배너·보상형 광고를 이번 개선의 필수 과제로 추가하지 않는다.

이미 광고 제거를 산 사람에게 무료 흐름이 좋아졌다는 이유로 불이익을 주지 않는다. Pro의 가치를 무료 불편에만 의존해 설명해서도 안 된다.
