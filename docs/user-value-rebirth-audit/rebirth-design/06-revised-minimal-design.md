# 기존 디자인을 유지하는 최소 변경 설계

2026년 10월 30일. **이 문서가 재검토 후의 개발 범위 기준이다.** 앞선 01~04와 8개 화면 시안에서 충돌하는 내용은 이 보완안으로 대체한다. 판단 근거와 원안의 문제는 [사용자 경험 검토](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/05-user-experience-review.md)에 있다. 이번에는 문서만 보완하며 앱 코드는 수정하지 않는다.

## 유지할 사용자 경험

오늘·캘린더·자동화·설정의 기존 화면과 디자인, 큰 잠금화면 미리보기, 템플릿 선택 위치, 인라인 작성창, 기존 저장·직접 반영 방식을 유지한다. 새 잠금화면 허브·공통 작성 시트·별도 중요 그룹·전역 적용 버튼을 만들지 않는다. 색상·타이포그래피·카드 외형·탭·화면 골격을 바꾸는 작업은 범위에서 제외한다.

필요한 기능적 수정은 기존 조작 자리에 작은 안내·기존 선택 컨트롤·바로가기 수준으로 한정한다. 새 UI를 만드는 대신 실제로 실패하거나 예상과 다른 결과를 만드는 연결을 고친다.

## 기존 자리에서 바뀔 부분

## 표시 선택에 대한 확정과 미해결 요구

### 이번 단계에서 확정하는 것

기존의 표시 날짜·규칙·전체/개별 선택·반복 시리즈 의미를 유지한다. 필터 밖 항목을 중요하다고 강제로 끼워 넣지 않는다. 규칙이 직접 선택이면 새 할 일은 자동 포함되지 않으며, 전체 선택이면 기존 방식으로 후보가 된다. 신규 규칙의 기본 선택은 현 동작을 따르고 기존 규칙을 새 기본값으로 재작성하지 않는다.

기본 정렬은 현재의 최신 수정순을 유지한다. 오래된 일 우선·시각 우선·별도 정렬 모드로 일괄 변경하지 않는다. 현재 정렬이 사용자의 중요도를 의미한다고 설명하지도 않는다. 템플릿·글자 크기·표시 면에 따라 실표시 수가 달라질 수 있다는 기존 제한은 유지한다.

| 상황 | 기대 결과 | 해결되는 범위와 남은 한계 |
| --- | --- | --- |
| 규칙에서 2개 선택 후 새 일반 할 일 10개 추가 | 선택 범위의 2개 유지, 새 일반 항목이 임의로 포함되지 않음 | U32에서 확인한 선택의 효용을 그대로 활용 |
| 규칙에서 6개 선택, 카드 수용량 5 | 현재 정렬의 앞부분만 보임. 편집 화면에서 초과 가능성을 알림 | 여섯 번째 중요한 일 보장은 아직 해결되지 않음 |
| 직접 선택한 할 일 완료 | 해당 발생분은 기존 완료 표시 설정에 따라 제외/표시. 미완료를 우선 보는 기본 사용에서는 다음 후보가 보임 | 완료 항목을 다시 미완료로 만들거나 데이터 삭제 금지 |
| 완료 취소 | 같은 발생분 미완료로 복귀, 현재 정렬과 표시 범위 재평가 | 새 우선 위치 복구를 약속하지 않음. 편집/수정 시각에 따른 위치 변화는 현 동작 기준 |
| 선택한 반복 항목 다음 발생 | 기존 시리즈 선택이 이어짐. 오늘 완료를 내일 완료로 복사하지 않음 | 새 ‘이번만/매번 우선’ 설정 불필요 |
| 미래로 날짜 변경 | 선택 날짜 후보에서 빠지고 새 날짜에 기존 정책으로 평가 | 오늘 공간을 예약하거나 날짜를 자동으로 오늘로 바꾸지 않음 |
| 날짜 고정·오늘 복귀 | 기존의 명시적 고정/복귀 그대로 | 캘린더를 구경하는 것만으로 고정 변경 금지 |
| 규칙의 범위가 비어짐 | 원래 범위 안의 빈 상태를 유지 | 다른 목록·개인 메모를 빈자리 보충용으로 노출하지 않음 |
| 자동 전환 중 기본 설정 확인/수정 | 기본 설정만 확인/수정, 켜져 있던 규칙은 유지 | 자동 전환 끄기는 기존 토글로 명시적으로 수행 |

이 표는 실제 시간 경과·모든 표면 검증을 마쳤다는 뜻이 아니라 유지해야 할 계약이다. 이전 1단계 수정은 재설계하지 않고 새 변경으로 영향을 받는 경로만 회귀 확인한다.

### 보류하는 최소 후보

기본 무료 표시나 수용량 초과 상황에서 ‘중요한 일이 밀림’은 여전히 남을 수 있다. 안내만으로 해결됐다고 출시 설명에 쓰면 안 된다.

실제 누적 사용자에게 기존 선택을 사용하게 해 다음을 확인한다. 필요한 일을 범위에 넣을 수 있는지, 작은 위젯의 첫 항목을 고를 수 있는지, 그 과정이 매일 반복되는지, 선택 후에도 기대한 항목이 빠지는지 관찰한다. 단순 설정 위치 문제면 기존 진입과 설명만 보완한다.

동작이 부족하다고 확인될 때만 **현재 표시 범위 안의 선택적 순서 조정 한 가지**를 검토한다. 기존 항목 선택 화면과 식별을 우선 활용하되 현재 코드에 순서 유지 기능이 있다고 가정하지 않는다. 무료 기본 범위에 노출하려면 수동 표시 선택의 최소 확장이라는 사실과 권한 범위를 별도로 명시한다. 자동 전환 Pro를 무료로 제공하는 것과 혼동하지 않는다.

이 후보에는 전역 우선순위·3개 제한·비활성 자리·반복 우선 범위·별도 그룹·자동 중요도 추천을 붙이지 않는다. 항목/시리즈 식별과 이월·연결 해제에서 순서를 안정적으로 유지할 수 없는 상태라면 출시하지 않는다. 검증 전 ‘중요한 일이 항상 보인다’고 약속하지 않는다.

## 작성과 표시의 정확한 분리

분리하는 것은 **입력 유형 선택과 표시 유형 설정**이다. 내용 수정의 정상적인 반영까지 막는 것은 아니다.

| 사용자 행동 | 기대 결과 |
| --- | --- |
| 할 일 표시 중 메모 작성 탭으로 이동·입력·취소 | 할 일 카드·템플릿·기본 표시 설정·자동 전환 불변 |
| 할 일을 새로 저장·편집·완료 | 원래 표시 범위 안이라면 내용 갱신. 표시 유형·템플릿은 불변 |
| 현재 표시 중인 메모를 수정해 저장 | 같은 메모 내용 갱신. 별도 적용 없음 |
| 표시하지 않는 메모 수정 | 해당 기록만 저장. 현재 표시 메모를 교체하지 않음 |
| 메모 편집의 ‘잠금화면에 표시’를 명시적으로 켜고 저장 | 기존 단일 표시 메모 선택을 교체. 템플릿·시간 규칙은 자동 변경하지 않음 |
| 템플릿/표시 내용을 기존 컨트롤에서 선택 | 기존의 명시적 표시 변경으로 처리. 입력 탭만 눌렀을 때와 구분 |
| 자동 전환이 개별 메모만 허용 | 선택한 메모만 허용. 새 메모를 저장해도 규칙의 목록을 임의 변경하지 않음 |

새 메모 작성의 기본 선택은 다음처럼 제한한다. 이는 사용자 기대를 확인해야 하는 설계 결정이며 이미 검증된 동작으로 간주하지 않는다.

- 기본 메모/혼합 표시에서 메모를 바로 교체하는 경로는 저장 한 번을 유지한다. 저장 결과가 ‘현재 표시 메모 교체’임을 기존 표시 선택 의미와 짧은 안내로 알린다.
- 할 일만 표시 중 새 메모를 기록할 때는 기존 선택 메모·표시 유형을 보존한다. 필요할 때만 기존 ‘잠금화면에 표시’ 선택을 사용하게 한다. 이 선택을 빠른 작성에 노출해야 한다면 기존 토글을 재사용하고 별도 화면·저장 후 적용 단계를 만들지 않는다.
- 시간 규칙의 개별 메모 필터 때문에 새 메모가 보일 수 없는 경우에는 기본적으로 기존 선택을 보존한다. “현재 구성에는 선택한 메모만 표시돼요”를 알리고 필요할 때 기존 규칙 편집으로 이동한다. 저장을 막거나 자동화 전체를 끄지 않는다.
- 표시 중인 기존 메모를 편집하는 경우에는 문맥으로 선택을 재계산하지 않고 기존 토글 값을 유지한다.
- 기존 단축어의 명시적인 메모 추가·교체 의미는 입력 탭 분리와 별도로 보존한다. 앱 내부 저장 기본값 변경을 공통 큐 처리에 일괄 적용하지 않는다. 해당 경로의 실제 메모 기대는 별도 검증한다.

위 방식은 기록용 메모 사용자와 빠른 표시 메모 사용자의 요구를 함께 보호한다. 기존 사용자의 탭 전환 자체를 표시 전환으로 쓰던 습관은 바뀔 수 있으므로, 현재 템플릿 컨트롤에서 같은 표시 전환을 찾을 수 있는지 실제 사용자에게 확인해야 한다. 이 경로가 더 번거롭다면 기본 행동 변경을 확대하지 않는다. 두 기능을 나누었다는 이유만으로 무조건 더 자연스럽다고 결론 내리지 않는다.

## 첫 표시와 계속 쓰기

현재 소개·입력·시작 화면을 유지한다. 실제 불편이 확인된 단축어 안내는 ‘설정 완료’로 오해시키지 않는 문구로 바꾼다. 기존 건너뛰기·나중에를 유지하고 첫 표시 성공 뒤 교육을 필수로 거치지 않고 오늘로 갈 수 있게 한다. 저장 실패 시 입력을, 시작 실패 시 저장한 기록을 보존한다.

사용자에게 잠금화면을 확인하도록 안내할 수 있지만 ‘확인했어요’라는 새 필수 버튼이나 새 성공 단계를 추가하지 않는다. 시작 성공·사용자 실제 시청·위젯 설치는 지표에서도 분리한다.

반복·미리알림·시간 전환을 이미 사용하는 사람에게 재설정·재연결·새 온보딩을 요구하지 않는다. 구성 선저장 때문에 막힌 경우에만 기존 저장 화면으로 바로 연결하고 돌아온다. 기존 구성이 있는 사람의 규칙 편집 동선은 바꾸지 않는다.

## 기존 유료와 무료 및 광고

기존 무료/Pro 경계·가격·상품·광고 제거·체험·복원을 유지한다. 먼저 표시나 순서 조정 후보를 아직 제공하지 않는 무료 혜택으로 홍보하지 않는다. Pro의 연동·고급 반복·자동 전환 가치를 기존 화면 문구로 보완하되 템플릿을 고른 사람에게 불필요한 새 소개를 강제하지 않는다.

핵심 작성·저장·완료/취소·외부 진입/복귀·시스템 설정 복귀·연결 및 표시 복구·구매/복원 중에는 전면 광고와 자동 부가 제안을 금지한다. 이 원칙을 기존 광고 허용 판정에 적용하는 것이 우선이며 새 광고 형식은 만들지 않는다.

현재 앱 오픈 광고가 안전한 노출 구간을 구분하지 못하면 해당 형식은 노출하지 않는다. 출처를 모르는 것을 광고 허용으로 간주하지 않는다. 전체 노출 중단이 필요할 수 있지만 이를 측정 없이 영구 수익 정책으로 확정하지 않는다. 광고 수익 감소와 앱 밖 완료·Pro 실수익을 같은 30일 창에서 비교한다. 무료 핵심을 제한하거나 Pro 구매자에게 광고를 되살리는 방식으로 보상하지 않는다.

| --- | --- | --- |
| P0 | 기존 화면·템플릿·설정·권리·자동 전환 상태 보존, 핵심 광고/제안 차단 | 익숙한 앱에서 하려던 행동을 중단 없이 끝냄 |
| P0 | 작성 유형 전환의 표시 설정 부작용 분리, 메모의 기존 빠른 수정·교체 보존 | 글을 쓰려다 카드가 바뀌지 않고 표시 중 내용은 정상 갱신 |
| P0 별도 | D-Day 메모·사진 구성의 관찰된 결과 불일치 영향 확인 | 보이는 결과를 저장·다시 사용할 수 있다는 신뢰 |
| P1 | 구성 저장 바로가기·표시 선택 한계 설명·기존 완료 취소 발견성·단축어 안내 | 막힌 동선만 줄이고 새 관리 화면을 만들지 않음 |
| P1 검토 | 누적 사용자의 기존 표시 선택 과제 | 이미 있는 기능으로 충분한지 판단. 기본 무료·초과 수용량 문제를 숨기지 않음 |
| 조건부 후속 | 기존 선택으로 부족하다고 확인된 순서 조정 최소 보강 | 매일 중요한 항목을 다시 고르는 부담이 실제 줄어들 때만 진행 |
| 보류 | 화면 재배치·전역 우선순위·새 자동 정렬·새 체험·광고 형식·새 관리 체계 | 기능을 늘려 사용을 복잡하게 만들지 않음 |

## 개발 전에 통과해야 할 사용자 과제

아래는 검증 계획이며 새 실사용 결과가 아니다. 기존 단순 할 일 사용자·메모를 바로 바꾸는 사용자·자동 전환/미리알림을 쓰는 Pro 사용자를 구분한다. 업데이트 전 설정을 가진 설치본으로 비교하고 일부 시나리오는 실제 날짜와 시간 경계를 넘긴다.

| 과제 | 통과 조건 |
| --- | --- |
| 기존 앱 그대로 열기 | 기존 탭·작성창·미리보기·템플릿 위치 유지. 자동 전환·구매·목록·반복 설정 그대로 |
| 할 일 화면에서 메모 기록 | 취소/저장만으로 기존 카드가 메모형으로 바뀌지 않음 |
| 매일 쓰는 표시 메모 수정·교체 | 기존 빠른 경로의 저장 횟수 유지. 별도 설정·적용 화면 필수화 없음 |
| 이미 쓰는 자동 전환 중 메모 작성 | 다른 시간 규칙의 메모나 범위가 몰래 바뀌지 않음 |
| 누적 30개에서 기존 표시 선택 | 중요 항목 포함과 실제 표시를 구분. 초과 시 미표시 사실을 이해하고 원본 보존 |
| 선택된 반복 완료·취소·다음 발생·날짜 변경 | 기존 범위/날짜 의미 유지. 새 ‘예약 자리’·우선 범위 관리 없음 |
| 구성 없이 첫 규칙 만들기 | 기존 구성 저장으로 바로 이동·저장 후 복귀. 새 생성 화면 학습 없음 |
| 처음 설치 후 첫 표시 | 기존 흐름에서 저장·시작 가능. 추가 교육/광고/강제 확인 없이 오늘로 이동 |
| 외부 완료·추가 후 돌아오기 | 기존 완료 기능 유지. 전면 광고·자동 결제/알림 제안 없음 |
| 기존 Pro 업그레이드와 테스트 복원 | 사진·D-Day·구성·고급 반복·원본 연결·권리 손실 없음. 재설정 강요 없음 |

조작 수는 실제 의도를 기준으로 비교한다. ‘표시 중 메모 고치기’, ‘현재 템플릿 바꾸기’, ‘할 일 바로 쓰기’가 기존보다 늘면 해당 설계를 다시 줄인다. 의도하지 않은 카드 변경을 막기 위한 명시적 선택 한 번은 무조건 실패가 아니지만, 실제 혼동을 줄였는지 함께 확인한다.

[기존 지표 설계](/Users/nam/projects/ios/locktodonote/docs/user-value-rebirth-audit/rebirth-design/04-delivery-validation-metrics.md)의 앱 밖 완료·저장 성공·의미 있는 사용일·권리 손실·30일 실수익 구분은 유지한다. 먼저 표시 이벤트·밀림 0 보장·새 필수 사용자 확인 수집은 확정 개발 범위에서 제외한다. 순서 문제가 미해결인 상태를 수치상 성공으로 바꾸지 않는다. 앱 실행 감소만으로 실패로 보거나, 새 관리 화면 방문 증가를 지속 사용 개선으로 해석하지 않는다.
